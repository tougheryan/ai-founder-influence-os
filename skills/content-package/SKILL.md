# content-package · 平台原生内容

## 目标

同一份真实素材可以服务多个平台，但每个平台必须是独立生产单元：共享事实、案例、观点、受众、目标和不可公开边界；不共享成稿，不从公众号长文改写小红书或视频号。

只生成参数 `platforms` 中明确选择的平台。支持且仅支持：

- `wechat`：公众号原生长文；
- `xhs`：小红书原生图文；
- `shipinhao`：视频号原生口播执行稿。

禁止输出抖音、朋友圈、未选平台或固定的“1+2+3”内容数量。

## 输入

- 必需：当前 run 已确认的 `pipeline/blueprint/` 平台内容蓝图；
- 必需：本期所选平台列表；
- 蓝图必须包含共享事实底稿、明确的写作依据、独立平台结构与风险边界；研究路径保留各平台研究依据，作者素材路径保留运行时核验的作者素材版本；
- 研究样本只用于判断受众需求、结构惯性和入口机制，不能照搬标题、观点、案例或表达。

当运行时明确核验 `research_mode=author_material` 时，本期未进行平台研究。以作者素材、已确认题目和方案组织所选平台内容；不补造研究样本、热门结论或效果承诺，也不因没有研究而要求作者重新找题。正文不能出现素材校验、未研究等内部工作说明；事实和经历仍必须有授权素材支持。其他路径继续使用已冻结研究，不允许凭提示词切换依据。

## 输出

通过 runtime 写入 `package`：

```bash
python3 $AIFIOS_HOME/skills/content-runtime/scripts/content_runtime.py \
  --project ~/ai-content-system \
  write --step package --slug {slug} \
  --content @/path/to/platform-native-content.md \
  --source "blueprint:{蓝图文件路径}"
```

## 质量门

- 平台章节必须与本期选择完全一致；
- 每个平台的标题、结构和表达能追溯到该平台研究依据；
- 不得出现“由公众号改写”“母稿拆解”等跨平台派生关系；
- 缺少事实时降低断言，不得补造案例、数字、客户、结果或引用；
- 视频号只交付脚本、镜头、字幕、B-roll 建议与发布文案，不生成额外视觉资产。

生成不是一次性吐稿。模型在输出前必须在内部完成“初稿 → 平台审稿 → 定向修订”，只输出修订后的最终内容包：

- 公众号检查：标题有具体读者或场景，开头在前 300 字建立场景、冲突和阅读收益，正文完成证据—判断—方法—行动的推进，避免正确但空泛的段落。
- 小红书检查：P1 负责停止滑动，P2 建立问题或证据，P3-P6 每页只推进一个判断，P7 总结可执行动作，P8 形成真实互动；不得把长文平均切成八段。
- 视频号检查：前三秒能独立成立，口播符合自然说话节奏，每个时间段都能拍摄和剪辑；不得把文章改成朗读稿。
- 三个平台检查：标题、开头、结构与互动问题必须各自成立；如果能看出某个平台是另一个平台的摘要或改写，必须重新生成该平台。
- 所有平台检查：删除空话、重复结论、模型自述和未经素材支持的精确断言；事实不足时明确边界，不用修辞掩盖证据缺口。
