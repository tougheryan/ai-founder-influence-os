# content-intake · 素材理解

## 作用

把原始素材变成结构化的内容原料。不是简单摘要，而是提取后续立项、角度生成、内容拆解和写作能直接使用的素材资产包。

第一性原则：`content-intake` 先回答“这份素材为什么值得被看见”，再回答“它应该被谁看见”，最后才回答“它应该怎么写”。这三步必须做，但默认藏在内部，不生成用户可见的中间报告。它仍然不能提前替用户写成稿，不替代立项判断，也不把推断包装成事实。

剃刀原则：素材理解报告不是漂亮摘要，而是事实资产包。只保留下游立项会使用的信息：来源、场景、人物、事件链、观点证据、情绪依据、案例可信等级、商业意图、不可公开信息和素材缺口。不能追溯的内容只能标记为推断或待核验。

默认不向用户展示素材理解报告。它是内部质量门，只有用户明确要求“分析素材/看报告”，或素材不足、事实风险、隐私风险阻断生产时，才把相关结论摘出来给用户。

在产品流程中，`content-intake` 只产出完整的内部素材理解报告，不直接产出主题候选或让操作者选主题。界面会先展示已分析的素材摘要，再强制完成 TikOmni 抓取与对标，随后才生成 6 条主题建议供操作者确认。

因此，写入 runtime 的本次输出必须是下方“输出结构”定义的完整 Markdown 报告。不得只输出 A-J 主题清单、推荐主题或面向用户的轻量摘要；它们会让内部素材资产包缺失必需章节，不能进入 TikOmni 研究。

## 触发方式

- `/content-intake`
- `理解素材`、`分析素材`、`拆解一下这个素材`
- `这个人/这件事值得写什么`

## 输入

任意形式的素材：
- 文字 / Markdown
- PDF / DOCX / 网页链接
- 语音转文字
- 图片（配 OCR 或人工描述）
- 聊天记录 / 会议纪要
- 用户口头描述

可选参数：
- `scenario`：素材场景类型，如未指定需主动询问或反推
- `platforms`：目标平台（wechat / xhs / shipinhao / douyin / moments），默认按一稿五发交付准备
- `research`：是否需要补充研究，默认 false。只有用户要求、素材涉及事实背景、行业数据或近期事件时才补充外部研究。

## 素材场景分类

收到素材后，先判断属于哪一类场景。场景决定后续的内容结构、标题逻辑和平台表达方式。如果用户没有明确说明，先根据素材反推并标注置信度；只有关键信息不足以继续生产时再询问。如果跨多个场景，以**主场景**为准，其他作为补充。

| 场景 | 核心用途 | 适合内容 | 主要平台 |
|---|---|---|---|
| **个人履历 / 经验 / 知识分享** | 建立专业身份和可信背书 | 职业经历、方法论、行业判断、复盘 | 小红书、公众号 |
| **访谈 / 嘉宾出席 / 演讲分享** | 将线下高价值对话沉淀为内容资产 | 活动纪实、观点金句、人物背书 | 公众号、小红书 |
| **个人成长 / 人生心得** | 增强真实感和情绪连接 | 转折、选择、压力、修复、长期主义 | 小红书、公众号 |
| **日常工作 / 生活记录** | 将碎片化日常变成稳定素材池 | 出差、会议、客户拜访、工作现场 | 小红书、公众号 |
| **业务 / 产品增长 / 引流获客** | 把内容转化为商业信任入口 | 客户案例、产品价值、服务说明、转化 CTA | 公众号、小红书 |
| **全球化表达 / 跨境内容** | 面向海外用户、东南亚华人和关注中国市场的专业人士 | 双语内容适配 | 公众号、小红书 |

## 内部内容策略画像

`## 0.1 内容策略画像` 是 intake 的硬性内部质量门。它不直接交付给用户，但必须驱动轻量主题选择门和后续内容结构。

必须包含：

- 素材为什么值得被看见：指出原文中的具体观点、事实或案例能回答读者的什么问题，以及依据和适用边界。真实、认知、方法等可作为判断角度，不要求凑够价值类别；只有观点时，不补写案例、背书或效果。
- 值得被看见指数：0-10 分，并说明扣分原因；素材弱时不要硬凑高分。
- 主受众 / 副受众：必须是具体人群，不能写“所有人、用户、客户、创业者”这类泛词。
- 用户可选主题候选：素材阶段保留具体问题和选题边界；当前工作台在已选平台研究完成后生成候选，不在研究前预设热门结论或为了数量扩写无依据方向。
- 核心判断句：一句话说明这条素材最值得传播的判断。
- 内容结构：写清后续成稿的叙事路径，如“客户问题 -> 旧做法失效 -> 新判断 -> 案例证据 -> 低压力评论诊断”。
- 爆款参考范围：只限定同场景、同平台、同人群、同行为目标的公开内容机制，不复制标题、正文、封面、镜头或评论；这会成为 `intake -> validate` 间必跑的 `market-signal` 公开对标质量门。
- 禁止写法：列出不能使用的表达，如泛观点、会议纪要、硬广、未核验数字、隐私细节。

## 工作流

1. **读取素材**：根据输入类型选择读取方式
2. **判断价值**：先判断素材为什么值得被看见；如果价值不足，降级为补素材或灵感备忘
3. **判断受众**：明确主受众、副受众和用户可选受众，不用“所有人”兜底
4. **判断写法**：根据场景、受众和风险边界确定内容结构、主题候选和禁止写法
5. **判断场景**：识别素材属于哪一类素材场景，如未明确则主动询问或反推，以主场景为准
6. **提取要素**：按人物、场景、观点、情绪、案例、商业意图、不可公开信息、素材质量判断提取内容资产
7. **补充研究**（可选）：调用 `aihot`/`hv-analysis` 或联网核查补充行业背景；外部研究必须和用户素材分开标注
8. **输出报告**：调用 content-runtime 写入 `pipeline/intake/`，并给出下一步建议

   示例：
   ```bash
   python3 $AIFIOS_HOME/skills/content-runtime/scripts/content_runtime.py \
     --project ~/ai-content-system \
     write --step intake --slug {slug} \
     --content @/tmp/intake-body.md \
     --source "用户输入"
   ```

## 场景化提取提示

不同场景的关注重点应有所倾斜：

- **个人履历 / 经验 / 知识分享**：重点提取可证明专业度的经历、方法论步骤、关键判断依据、可复用框架
- **访谈 / 嘉宾出席 / 演讲分享**：重点提取金句、对话冲突、人物背景、现场细节、观点交锋
- **个人成长 / 人生心得**：重点提取转折点、情绪曲线、具体困境、修复过程、价值观变化
- **日常工作 / 生活记录**：重点提取真实场景、可视化细节、节奏变化、可被共鸣的日常冲突
- **业务 / 产品增长 / 引流获客**：重点提取产品价值、用户痛点、转化路径、客户案例、CTA 入口
- **全球化表达 / 跨境内容**：重点提取跨文化差异、海外受众关注点、双语表达难点、区域市场特征

## 质量原则

- 不编造素材中没有的信息
- 不可公开信息必须显式标出
- 情绪判断要有文本依据
- 商业意图要区分"显式"和"隐式"
- 每个观点要标注来源位置
- 一手事实、转述信息、模型推断、外部背景必须分开
- 没有证据的数字、身份、公司、客户案例不得写成事实
- 素材不足时给出补充清单，而不是用套话填满报告

## 交付自检

写回 runtime 前逐条检查：

- `素材场景` 必须包含主场景、判断依据、推荐优先平台、素材来源和事实边界。
- `内容策略画像` 必须包含为什么值得被看见、值得被看见指数、主受众/副受众、A-J 共 10 个用户可选主题候选、核心判断句、内容结构、爆款参考范围和禁止写法；这些判断默认只作内部质量门，不要交付成报告。
- `人物` 必须说明核心人物/说话人，不能只有“用户/客户/某人”。
- `场景` 必须有时间/背景或关键事件链，并标注缺失信息。
- `观点` 必须至少有一条明确观点，并写出证据位置。
- `情绪` 必须有主情绪，并尽量给出情绪曲线、文本依据或可共鸣点。
- `案例` 优先写核心案例、支撑细节、可展开度和可信等级；如果原始素材确实没有案例，不能硬编，必须写“当前无可追溯核心案例 / 素材不足待补”，并在 `素材质量判断` 中把下游可用性标为“需要补素材 / 只适合做灵感备忘 / 不可立项”。
- `商业意图` 必须区分产品/服务/品牌信息、目标受众和转化路径；如果素材未明确，要标注“隐式推断”。
- `不可公开信息` 不能写“无”，至少写明隐私/商业机密/敏感关系和处理建议。
- `素材质量判断` 必须包含信息完整度、可信度、最值得深挖的点、当前缺口和下游可用性。

写入后建议立刻运行：

```bash
python3 $AIFIOS_HOME/skills/content-runtime/scripts/content_runtime.py \
  --project ~/ai-content-system \
  validate --step intake --file pipeline/intake/{文件名}.md
```

`validate` 会调用 runtime 的素材理解质量审计。主场景、素材来源、事实边界、观点证据位置、不可公开信息和下游可用性属于硬门槛，阻断问题必须修复后再进入 `content-validate`。如果只是缺少核心案例或可信等级，但报告已明确标为“需要补素材 / 待核验 / 不可立项”，会作为复核提醒保留；立项报告必须显式承接。

## 与其他 Skill 的关系

- 下游：先进入轻量主题选择门；主题确认后必须运行 `market-signal` 公开样本抓取/对标，再进入 `content-validate`（选题立项）→ `content-blueprint` → `wechat-writer` → `content-package`。没有公开样本时保留“样本不足”状态，不得跳过后声称已经对标。
- 可调用：`aihot`、`hv-analysis`，必要时联网核查公开来源

## 输入/输出示例

### 示例 1：语音转文字素材 → 素材理解报告

**输入**
```text
（语音转文字片段）
上周我连夜用 Codex 改一个老项目，本来预计要三天的活，结果一晚上就搞定了。我当时特别兴奋，但又有点慌，因为以前总觉得写代码是护城河，现在感觉这护城河可能没我想象的那么宽。我录这个是想聊聊我对 AI 编程的真实感受。
```

**预期输出**
```markdown
# 素材理解报告 · AI 编程助手的真实冲击

## 0. 素材场景
- 主场景：个人成长 / 行业观察（混合）
- 素材来源：语音转文字
- 事实边界：一手体验是“连夜用 Codex 改老项目”；“护城河变窄”属于说话人的主观判断

## 1. 人物
- 说话人：有 3 年左右开发经验的技术从业者
- 身份：创业者或技术负责人
- 情绪：兴奋 + 焦虑

## 2. 场景
- 时间：上周
- 事件链：预计三天改完老项目 → 使用 Codex 一晚完成 → 产生兴奋和职业焦虑
- 缺失信息：项目类型、代码规模、是否有人工返工

## 3. 观点
- Codex 显著提升了编码效率（三天活一晚上完成）
  - 证据位置：用户原话“预计要三天的活，结果一晚上就搞定了”
- 写代码作为职业护城河的判断需要重新评估
  - 证据位置：用户原话“护城河可能没我想象的那么宽”

## 4. 情绪
- 主情绪：兴奋、慌张
- 文本依据：“特别兴奋，但又有点慌”

## 5. 案例
- 核心案例：用 Codex 改老项目
- 可信等级：一手经历，但缺少项目规模和返工成本

## 6. 商业意图
通过真实体验建立专业信任，吸引对 AI 编程焦虑/好奇的读者

## 7. 不可公开信息
- 老项目名称、客户信息、代码细节不可公开
- 处理建议：发布时只保留工作量对比和心态变化，不暴露项目背景

## 9. 素材质量判断
- 信息完整度：中
- 可信度：一手经历可信，但效率提升数字需要谨慎表述
- 当前缺口：项目规模、返工成本、最终质量
- 下游可用性：可进入立项，但建议补一次“AI 写错/人工把关”的具体细节
```
