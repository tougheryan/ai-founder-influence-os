# content-blueprint · 平台内容蓝图

## 作用

把同一份真实素材组织为一份“共享事实底稿 + 平台独立蓝图”。它不是公众号母版，也不是跨平台改写源。

共享层只包含事实、案例、观点、受众、目标和不可公开边界。研究路径中，各平台分别读取自己的研究样本；作者素材路径中，沿用作者题目和已核对素材，分别组织所选平台的结构。

## 输入

- 当前 `content-intake` 素材理解报告；
- 本期所选平台：仅 `wechat`、`xhs`、`shipinhao` 的非空子集。
- 研究路径：当前 `content-validate` 立项报告及本期 TikOmni 研究快照与 SHA-256。
- 作者素材路径：运行时已明确选择 `research_mode=author_material`，并校验本期不可变作者素材记录、题目、平台与当前素材版本。仅文字声称跳过研究不能启用此路径；缺少研究或研究失败也不能自动切换。

作者素材路径不要求 `content-validate` 或平台样本。上游研究字段与各平台研究依据明确写“本期未进行平台研究；依据作者素材”，不生成样本数、热度或市场验证结论。保留事实来源、隐私、写作要求与人工确认。服务端写入真实素材记录路径与摘要，模型不得自行编造绑定。方案的确认状态默认待作者确认，不能由模型代为确认。

## 输出

通过 runtime 写入 `blueprint`：

```bash
python3 $AIFIOS_HOME/skills/content-runtime/scripts/content_runtime.py \
  --project ~/ai-content-system \
  write --step blueprint --slug {slug} \
  --content @/path/to/platform-blueprint.md \
  --source "validate:{validate路径};intake:{intake路径};market:{研究报告路径}"
```

必须包含：

```markdown
# 平台内容蓝图 · {主题}

## 0. 上游约束
- validate 报告路径：...
- intake 报告路径：...
- TikOmni 研究快照：...
- TikOmni 快照 SHA-256：...
- 本期平台：...

## 1. 共享事实底稿
- 可核验事实：...
- 可公开案例：...
- 核心观点：...
- 目标受众与业务目标：...
- 不可公开边界：...

## 2. 公众号独立蓝图
- 平台研究依据：{公众号样本与分级}
- 原生选题与标题假设：...
- 长文结构与证据分配：...
- 排版、评论和商业收口：...

## 3. 小红书独立蓝图
- 平台研究依据：{小红书样本与分级}
- 原生选题与封面三句话：...
- P1–P8 八页卡片结构：...
- 正文、结尾问题和标签方向：...

## 4. 视频号独立蓝图
- 平台研究依据：{视频号样本与分级}
- 原生选题与3秒钩子：...
- 口播推进、镜头和字幕任务：...
- 发布文案与评论承接：...

## 5. 平台差异检查
- 各平台共享哪些事实：...
- 各平台为何采用不同入口与结构：...
- 明确：不存在母稿派生关系。

## 6. 人工确认清单
- 选题、证据、隐私、商业承诺与平台选择是否一致；
- 确认状态：待作者确认
```

只保留本期已选平台的独立蓝图章节。平台样本数据不足时，只标记该平台待补证，不阻断其他平台蓝图。
