# content-repurpose · 跨平台发布改编

## 作用

`content-package` 负责一篇母稿的标准全量交付；本 Skill 用于已有成稿需要补做、重做或单独优化某个平台时。它不重写事实，不把一个平台的排版原样搬到另一个平台，也不生成或上传 MP4。

每个目标平台都必须产出可直接填写、粘贴或交给视觉/拍摄执行的发布态内容：

- 公众号：标题、摘要、首图策略、HTML 排版选择和文章结构；
- 小红书：标题、封面三行、正文、标签、页卡顺序和评论承接；
- 视频号、抖音：标题、发布文案、话题、封面、3 秒钩子、可用脚本与拍摄清单；
- 朋友圈：选图顺序、短文案和互动句。

## 输入

- 源成稿：同一 `slug` 的 `pipeline/final/`、`pipeline/package/` 或 `pipeline/xhs/`；
- 目标平台：`wechat`、`xhs`、`shipinhao`、`douyin`、`moments` 或 `all`；
- 可选：已授权的图片、截图、数据、录屏和不可公开信息；
- 必须继承源稿的事实边界、素材授权、核心判断和不做承诺的限制。

源稿缺少一手证据、授权或所需画面时，要写明“需要补充的素材”，不能用猜测补齐，更不能把概念图或 AI 图当作事实证据。

## 输出

通过 runtime 写入 `platform-adapt`：

```bash
python3 $AIFIOS_HOME/skills/content-runtime/scripts/content_runtime.py \
  --project ~/ai-content-system \
  write --step platform-adapt --slug {slug} \
  --content @/path/to/platform-adapt.md \
  --source "package:{源内容路径}"
```

只生成本次目标平台对应的章节；`all` 时生成全部章节。不得留下占位字段。

## 质量门

- 必须有 `## 0. 原文信息`、至少一个目标平台发布稿、`## 6. 平台差异对照` 和 `## 7. 下一步执行指令`。
- 每个目标平台都必须有完整的发布字段、具体改编/执行内容和素材缺口说明。
- 视频号、抖音章节只交付脚本和发布字段，不声称已生成视频、自动上传或已经发布。
- 不得新增原文没有的数字、案例、客户信息、截图内容或效果承诺。
