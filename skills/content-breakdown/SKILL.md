# content-breakdown

## 作用

把 `validate` 与 `angle` 的结论收敛为可执行 brief，供 `wechat-writer`、`content-package`、`xhs-card` 和视觉流程使用。

## 输入

- 已通过的立项报告
- 选定角度
- 可用事实、案例、来源和风险边界
- 目标平台：`wechat`、`xhs` 或两者

## 输出

```markdown
# 内容拆解方案 · {标题}

## 0. 上游约束
- 主题：
- 目标读者：
- 核心判断：
- 证据边界：
- 不可公开信息：

## 1. 标题方案
### 公众号
- 主标题：
- 备选：

### 小红书
- 发布标题：
- 封面三行：

## 2. 结构与素材
- 公众号正文结构：
- 小红书 P1-P5 结构：
- 必须引用的事实：
- 需要补充的素材：

## 3. 评论与转化
- 公众号评论区问题：
- 小红书评论区问题：
- 合规边界：

## 4. 下一步
- 公众号：`/content-write`
- 小红书：`/content-xhs`
```

## 规则

- 标题和首段必须回应具体读者场景，不只写抽象概念。
- 证据不足时明确标注补充项，不把推断写成事实。
- 所有下游产物必须保持同一 `slug` 与风险边界。
