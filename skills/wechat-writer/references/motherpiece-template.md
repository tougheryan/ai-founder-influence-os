# 公众号长文母版模板

## 生产顺序

1. 读取 confirmed blueprint。
2. 复述核心判断、标题假设、证据链和风险边界。
3. 写 3000-4000 字正文。
4. 在隐藏块中声明母稿字数、标题决策来源和排版交接卡。
5. 写入 `write --step write` 并运行 `validate --step write`。

## 选题立项卡

- validate 报告路径：
- 立项结论：通过 / 有条件通过 / 不通过
- 决策理由：
- 商业成立性判断：
- 平台首发策略：
- 风险提示：

只有立项结论为「通过」，且 `content-blueprint` 人工确认状态为 `confirmed` 或 `已确认` 时，才进入 wechat-writer。

## 标题决策卡

- blueprint 工作标题：用于约束正文的中心问题、核心判断和第一屏承诺，不等同最终发布标题
- 正文写作标题：写作阶段可保留工作标题或临时标题，但不能扩大事实和商业承诺
- package 标题候选：由 `content-package` 做至少 5 组标题测试后决定
- 标题来源：只能使用 `blueprint 标题假设` / `package 标题候选`；人工修改必须回写并追溯到 blueprint/package，不能作为独立来源
- 标题风险：夸大、绝对化、收益承诺、身份背书、事实不可证

标题两阶段规则：blueprint 工作标题约束正文；package 标题候选测试至少 5 组。

## 正文结构卡

wechat-writer 默认写成 3000-4000 字公众号思想母版。结构建议：

- 开头：用目标读者正在经历的真实困惑破题，不急着介绍作者
- 第一段判断：明确这篇文章反对什么误区、提出什么新判断
- 章节 1：场景和问题，解释读者为什么卡住
- 章节 2：证据和案例，证明判断不是口号
- 章节 3：方法或框架，给读者可复述的理解
- 章节 4：商业或时代洞察，回到为什么现在必须重看这个问题
- 结尾：收束到产品/服务承接、评论互动和下一步行动

## 身份与署名卡

- 创作名片：`brain/creative-library/profile.json` 路径、schema、版本与 `initialized` 状态
- 当前 run 身份证据：授权素材与 confirmed blueprint 路径
- 第一人称边界：可用的真实经历、不可推断的字段
- 署名决策：不署名 / 使用创作名片已确认的创作者名

创作名片未初始化或本稿未明确确认署名时，正文不输出作者行、账号名或固定尾注。

## 可拆资产标注

写作时在隐藏自检块中标注：

- 可拆平台判断句：
- 可拆图文页结构：
- 可做封面字：
- 可做置顶评论：
- 可做高意向评论回复：

这些标注供 `content-package` 使用，不能牺牲母稿完整性。

## 排版交接卡

- 源母稿路径：
- 最终标题：
- 封面字：
- 摘要：
- HTML 风格建议：
- callout 段落：
- 图片需求：
- CTA 位置：
- 预览检查状态：

排版工具只做阅读体验、HTML 和视觉层优化，不改写观点、事实和商业承诺。`content-visual` 和 `dbs-wechat-html` 不得改变文章的核心判断、标题承诺、证据口径和商业收口。

## 隐藏自检块扩展

成稿末尾必须包含隐藏自检块 `AIFIOS-WRITE-CHECK`，供后续工具读取。至少包含：

```markdown
<!-- AIFIOS-WRITE-CHECK
身份真源 - 创作名片：未初始化 / brain/creative-library/profile.json@v{n}；当前 run 素材：...；署名：不署名 / 已确认
选题立项结论：
母稿字数 - 3200-3800，最终以正文有效中文内容估算；低于 3000 或高于 4000 必须重写
标题决策来源 - blueprint 标题假设：工作标题《AI 编程之后，创始人真正要学会的是审稿》；package 标题候选：主标题《Codex 像一个超人实习生》
正文模板执行：
排版交接卡 - 封面字：AI 编程不是少写代码；摘要：一次 Codex 工作流实测后，我发现真正变贵的是人的审查能力；重点卡片：人工把关三层；引用：工具提效不等于责任消失；配图建议：工作流截图脱敏示意；CTA：留言你的工具使用场景；评论区首问：你现在最担心 AI 编程哪一步失控？

-->
```

发布前待检查项必须覆盖事实来源、隐私边界、标题承诺、封面字、评论区互动钩子、合规报告和质量报告。
