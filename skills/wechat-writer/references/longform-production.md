# 公众号长文三段式生产法

## 目录

1. 适用场景

3. Phase 1 写作任务卡
4. Phase 2 证据台账
5. Phase 3 文章骨架

## 1. 适用场景

当 `wechat-writer` 从 `content-blueprint` 进入公众号思想母版写作时，必须先完成三段式生产，不要直接生成全文。

第一性原则：长文不是把 brief 拉长，而是把一个值得相信的判断说清楚。

三段式生产的目的：

- 防止绕过上游约束。
- 防止用想象补真实细节。
- 防止只有观点，没有证据。
- 防止只有信息，没有题眼。
- 防止传播心理只停留在 brief，正文没有真正戳中读者。
- 防止结尾散掉，无法形成商业信任资产。
- 防止把“风格”误解成语气皮肤，导致素材和表达任务错配。

## 2. Phase 0 风格决策

先按 `style-matrix.md` 选择风格。如果用户指定风格，先检查证据是否支持；如果用户未指定，系统自动推荐。

风格决策必须回答：

```markdown
推荐风格
- 用户指定：无 / {style-id}
- 系统推荐：{style-id}（置信度：高/中/低）
- 最终采用：{style-id}
- 备选风格：{style-id} / {style-id}
- 选择依据：素材场景、证据类型、商业目标、读者处境、风险边界
```

硬规则：

- 没有一手体验，不选 `product-experience`。
- 没有客户授权和结果口径，不选 `case-breakdown`。
- 企业家兴衰叙事必须有公开时间线和多方事实，不做单因归因。
- 热点解读必须核验最新信息；不能核验时写 `review`。
- 风格决策必须进入隐藏自检块的 `推荐风格 - ...`。

## 3. Phase 1 写作任务卡

先从 blueprint 提炼一张内部任务卡。任务卡不要放进正文，但要进入隐藏自检块的摘要。

任务卡必须回答：

```markdown
写作任务卡
- slug：...
- 身份真源：创作名片路径与版本 / 未初始化；当前 run 授权素材路径
- 署名决策：不署名 / 创作名片已确认的创作者名（本稿已确认）
- 推荐风格：deep-narrative / founder-rise-fall / business-insight / method-playbook / product-experience / interview-speech / hotspot-analysis / case-breakdown / personal-reflection
- 文章原型：调查实验型 / 产品体验型 / 现象解读型 / 工具分享型 / 方法论分享型 / 复盘经验型
- 题眼：本文反对什么、支持什么、重新解释什么
- 目标读者：谁会读，以及他当前卡在哪里
- 核心判断：读者看完后应记住的一句话
- 传播心理：从 blueprint 的 `目标读者与情绪入口` 和 `评论区互动预埋` 摘出沉默解除、满足动机、有效立场、信念结构和受众还想听什么
- 情绪曲线：开头情绪 → 中段冲突 → 结尾余味
- 商业目标：建立信任 / 引导咨询 / 服务说明 / 产品教育 / 社群转化
- 发布风险：隐私、硬数字、版权、平台规则、夸大承诺
```

硬规则：

- `题眼` 不能等于主题名。
- `核心判断` 不能写成“很重要”“值得关注”。
- `目标读者` 必须具体到身份 + 场景。
- `传播心理` 必须来自 `content-blueprint`，不能临时编一套受众心理。
- `身份真源` 必须指向当前项目的已确认创作名片和当前 run 素材；未初始化就明确记录，不得回退到预置作者。
- 署名必须同时满足「创作名片有创作者名」与「当前稿件已确认署名」；否则不输出作者行。
- `推荐风格` 必须和素材证据、读者处境、商业目标匹配。
- 如果无法写出题眼，返回 `content-blueprint` 重做，不进入正文。

## 4. Phase 2 证据台账

再建立证据台账。正文里每个核心判断，至少要有一条证据支撑。

证据类型：

- 一手素材：用户口述、访谈、演讲、真实经历。
- 具体场景：时间、地点、人物、动作、对话、页面、截图、代码、评论区。
- 用户原话：客户、读者、访谈对象、评论区的真实表达。
- 公开来源：报告、论文、公告、财报、公开数据。
- 对标样本：同平台爆款样本、标题、开头、评论需求、转化机制。
- 作者已验证体验：亲自测试、实际项目、复盘记录。

台账格式：

```markdown
证据台账
| 判断 | 证据 | 类型 | 可公开程度 | 处理方式 |
|---|---|---|---|---|
| ... | ... | 一手素材/公开来源/... | 可公开/匿名/不可公开 | 原文使用/改写/只保留结论 |
```

硬规则：

- 至少 2 类证据进入正文。
- 不可公开的证据只能转成抽象判断，不能写出人名、客户名、项目名、截图细节。
- 硬数字必须有来源、时间口径或保守表达。
- 缺少关键证据时，隐藏自检块的 `质检结论` 写 `review`。

## 5. Phase 3 文章骨架

最后生成文章骨架。骨架不是小标题堆砌，而是正文推进顺序。

骨架必须包含：

```markdown
文章骨架
1. 开头场景：用哪个真实场景/反常识事实进入
2. 读者处境：读者为什么会误判或卡住
3. 第一推进：第一个证据如何支撑题眼
4. 第二推进：第二个证据如何带出更深判断
5. 反方理解：为什么相反看法也有合理性
6. 洞察层：这件事背后的机制、时代变化或信任结构
7. 方法/启发：读者能带走的判断标准或动作
8. 商业收口：自然引导到评论、咨询、复盘、产品或服务
```

硬规则：

- 开头不能从概念定义开始。
- 中段不能连续三段都是抽象观点。
- 反方理解必须是“真实处境”，不能是稻草人。
- 方法/启发必须能执行，不能只写“长期坚持”。
- 商业收口必须轻，不要硬卖，不要突然消失。

## 6. Phase 4 传播心理兑现

最后把 `content-blueprint` 的 `## 3. 目标读者与情绪入口` 和 `## 8. 评论区互动预埋` 翻译成正文推进策略。它不是另一个小标题，而是决定开头、转场、冲突和结尾怎么写。

必须形成这组内部决策，并写入隐藏块的 `传播心理兑现` 字段：

```markdown
传播心理兑现
- 沉默解除：开头替读者说出什么没说出口的情绪/处境
- 满足动机：正文满足身份认同、信息价值、情绪宣泄或社交资本中的哪几项
- 有效立场：作者站在哪一边，不站在哪一边
- 传播入口：谁最可能第一批转发/评论，以及他为什么愿意转发
- 信念结构：确认受众什么信念，挑战受众什么行为
- 受众情绪底层：焦虑、兴奋、怕丢脸、希望被理解、想获得掌控感等
- 受众还想听什么：读者看完后自然会追问的模板、清单、案例或下一篇
```

正文推进建议：

```
沉默解除开头 → 真实案例承接 → 信念冲突展开 → 方法论解决 → 商业收口
```

硬规则：

- 缺少 `## 3. 目标读者与情绪入口` 时，不进入正文。
- 传播心理兑现不能只复制上游文字，必须说明它如何落到可见正文。
- 如果正文没有明显写出读者隐秘情绪、有效立场、信念冲突和后续需求，隐藏块 `质检结论` 写 `review`。

## 7. 正文写作要求

完成任务卡、证据台账、文章骨架和传播心理兑现后，再写正文。

正文写作时：

- 只保留文章阅读体验，不展示任务卡和证据台账。
- 用 H1 写标题。
- 按当前客户创作名片和 `style-adaptive.md` 自然推进，除非是方法论清单文章，否则避免大量小标题。
- 让证据自然进入正文，不要写成报告。
- 对缺口保持诚实，不要用想象补真实经历。
- 结尾按 blueprint 的商业收口和互动预埋自然完成；不追加预置口播或未确认署名。
- 末尾写 `AIFIOS-WRITE-CHECK` 隐藏自检块。

隐藏块必须包含：

```markdown
<!-- AIFIOS-WRITE-CHECK
上游 brief - ...
身份真源 - 创作名片：未初始化 / brain/creative-library/profile.json@v{n}；当前 run 素材：...；署名：不署名 / 已确认
推荐风格 - ...
写作任务卡 - ...
证据台账 - ...
文章骨架 - ...
必用证据 - ...
传播心理兑现 - 沉默解除：...；满足动机：...；有效立场：...；传播入口：...；信念结构：...；受众情绪底层：...；受众还想听什么：...
风险边界 - ...
商业收口 - ...
质检结论 - pass/review
-->
```

## 8. 发布前自查

成稿后问 9 个问题：

1. 这篇文章的题眼，能不能被一句话复述？
2. 读者处境是不是具体到一个真实的人？
3. 是否至少有 2 类证据进入正文？
4. 是否有明确判断，而不是资料搬运？
5. 是否理解了反方或普通读者的合理处境？
6. 是否有一个今天就能执行的判断标准或动作？
7. 商业收口是否自然？
8. 最终采用的风格是否真的匹配素材证据和商业目标？
9. 上游目标读者情绪入口和评论互动预埋是否被正文兑现，而不是只在隐藏块复述？
10. 自检块里的风格、证据、传播心理、风险和收口，是否都能在正文里找到对应内容？

任一项不通过，先修正文，再写入 runtime。
