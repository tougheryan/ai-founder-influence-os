# 公众号长文风格矩阵

## 1. 第一性原则

风格不是换一层语气，而是决定一篇长文如何调度证据、推进判断、承接商业关系。

`wechat-writer` 默认不携带主笔人格。作者身份、立场和表达偏好以当前客户已确认的创作名片、创作规则与本次 run 授权素材为真源。风格模式只决定本篇文章更像一次深度叙事、商业洞察、方法复盘、访谈沉淀，还是案例拆解。

硬规则：

- 用户明确指定风格时，优先采用用户选择。
- 用户选择与素材证据冲突时，不强行写。改用更安全的系统推荐风格，并在隐藏自检块标记 `review`。
- 没有一手素材，不写成一手经历；没有公开来源，不写硬数字；没有真实结果，不写案例成效。
- 创作名片未初始化时，不推断作者姓名、账号、履历、公司、第一人称经历或署名。
- 风格选择必须进入写作任务卡和 `AIFIOS-WRITE-CHECK` 隐藏块，方便后续复盘。

## 2. 风格决策输出

写正文前，必须形成这组内部决策，并把摘要写入隐藏块的 `推荐风格` 字段：

```markdown
推荐风格
- 用户指定：无 / {style-id}
- 系统推荐：{style-id}（置信度：高/中/低）
- 最终采用：{style-id}
- 备选风格：{style-id} / {style-id}
- 选择依据：素材场景、证据类型、商业目标、读者处境、风险边界
```

可先调用脚本生成第一版推荐：

```bash
python3 skills/wechat-writer/scripts/style_recommender.py --file {blueprint文件路径}
```

脚本只做稳定路由和风险提示。最终采用风格仍必须结合上游证据、用户指定和禁区清单判断。

## 3. 可选风格模式

| style-id | 中文名 | 适用素材 | 证据优先级 | 结构节奏 | 禁忌 | 商业收口 |
|---|---|---|---|---|---|---|
| `deep-narrative` | 深度叙事型 | 趋势、事件、个人观察、行业变化 | 真实场景 > 人物细节 > 公开背景 > 作者判断 | 具体场景 → 冲突 → 证据递进 → 时代洞察 → 余味 | 空泛宏大叙事、只有情绪没有证据 | 建立长期信任，引导评论/私信讨论 |
| `founder-rise-fall` | 企业家兴衰叙事型 | 企业家、公司兴衰、关键决策、时代周期 | 公开事实 > 时间线 > 关键决策 > 反方解释 | 高光时刻 → 关键转折 → 决策代价 → 时代结构 → 客观启发 | 成王败寇、道德审判、未经核实硬数字 | 引导到战略复盘、案例研究、商业判断 |
| `business-insight` | 商业洞察型 | 行业判断、增长、产品、获客、商业模式 | 业务场景 > 客户处境 > 数据口径 > 对标样本 | 读者误区 → 底层机制 → 判断框架 → 行动标准 | 把商业词堆成报告、没有明确立场 | 引导诊断、咨询、陪跑或产品教育 |
| `method-playbook` | 复盘方法论型 | 个人实践、项目复盘、经验总结、操作指南 | 一手过程 > 做对做错 > 结果反馈 > 可执行步骤 | 结果先行 → 背景 → 做对什么 → 做错什么 → 如果重来 | 空泛鸡汤、伪方法论、只讲成功不讲失败 | 引导读者照着检查或提交问题 |
| `product-experience` | 产品体验型 | 工具体验、AI 产品、真实测试、工作流改造 | 实测过程 > 截图/页面/动作 > 失败片段 > 对比体验 | 好奇心 → 亲自下场 → 逐步展示 → 发现问题 → 工作流收束 | 没试过却写成体验、只夸不说限制 | 引导工具清单、工作流咨询或社群讨论 |
| `interview-speech` | 访谈演讲转写型 | 访谈、演讲、圆桌、直播、播客转录 | 原话 > 现场场景 > 主讲人身份 > 观点重组 | 现场切入 → 3-5 个核心观点 → 作者旁白连接 → 可复用启发 | 伪造金句、改写到失去说话人真实语气 | 沉淀人物背书，引导二次传播/合作咨询 |
| `hotspot-analysis` | 热点解读型 | 新闻、政策、模型发布、行业突发事件 | 最新公开来源 > 多方口径 > 影响范围 > 作者判断 | 发生了什么 → 主流误读 → 深层机制 → 影响预判 → 行动建议 | 过期信息、单一来源、断言未来 | 引导关注后续、咨询判断或资料包 |
| `case-breakdown` | 案例拆解型 | 客户案例、项目案例、业务转化、失败复盘 | 授权素材 > 问题场景 > 行动链路 > 结果口径 | 具体问题 → 采取动作 → 结果反馈 → 为什么有效 → 可迁移原则 | 未授权客户细节、夸大结果、隐去失败成本 | 引导同类业务诊断、服务说明 |
| `personal-reflection` | 个人成长反思型 | 选择、压力、长期主义、创始人心态 | 真实经历 > 情绪节点 > 反思边界 > 读者共鸣 | 一个真实瞬间 → 内心冲突 → 重新理解 → 温和行动 | 装深沉、泛鸡汤、假经历 | 建立人格信任，引导留言和关系沉淀 |

## 4. 自动推荐规则

按 5 个维度给每个候选风格打 0-2 分，选择总分最高者。分差小于 2 分时，保留 1-2 个备选风格。

1. **素材场景匹配**
   - 访谈/演讲优先 `interview-speech`
   - 产品实测优先 `product-experience`
   - 企业家/公司周期优先 `founder-rise-fall`
   - 客户项目优先 `case-breakdown`
   - 个人实践复盘优先 `method-playbook`

2. **证据类型匹配**
   - 有完整时间线和公开资料，适合 `founder-rise-fall` / `hotspot-analysis`
   - 有一手过程和失败细节，适合 `method-playbook` / `product-experience`
   - 有客户授权和结果口径，适合 `case-breakdown`
   - 只有观点和少量素材，优先 `business-insight`，并标记证据缺口

3. **商业目标匹配**
   - 建立专业判断，优先 `business-insight`
   - 引导咨询/陪跑，优先 `case-breakdown` 或 `method-playbook`
   - 人格信任和长期关系，优先 `deep-narrative` 或 `personal-reflection`
   - 人物背书和活动传播，优先 `interview-speech`

4. **读者处境匹配**
   - 读者需要看懂趋势，优先 `deep-narrative` / `hotspot-analysis`
   - 读者需要知道怎么做，优先 `method-playbook`
   - 读者需要判断要不要买/用，优先 `product-experience`
   - 读者需要相信你能解决同类问题，优先 `case-breakdown`

5. **风险与证据完整度**
   - 涉及最新事实、价格、政策、模型能力时，必须核验最新来源；不能核验则标记 `review`。
   - 涉及企业家兴衰时，必须保持客观平衡，避免单因归因。
   - 案例未授权时，不选 `case-breakdown`，改为 `business-insight` 或 `method-playbook`。
   - 证据不足时，不选强叙事风格，避免写出假细节。

## 5. 风格与文章原型的关系

风格模式决定文章的“表达任务”，文章原型决定局部写法：

- `product-experience` 常搭配产品体验型、调查实验型。
- `method-playbook` 常搭配方法论分享型、复盘经验型。
- `business-insight` 常搭配现象解读型、方法论分享型。
- `deep-narrative` 常搭配故事型、现象解读型。
- `founder-rise-fall` 常搭配故事型、热点解读型、复盘/经验型。
- `interview-speech` 常搭配故事型、纯观点型。
- `case-breakdown` 常搭配复盘/经验型、痛点型。

不要因为选了某个风格，就机械套用固定小标题。公众号正文仍然优先保持自然阅读体验。
