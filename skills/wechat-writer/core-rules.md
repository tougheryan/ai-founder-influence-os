## 默认编辑原则

文章的价值观、口号、立场和人格必须来自当前客户已确认的创作名片、创作规则与本次 run 素材。本 skill 不提供预设口号或主笔人格。

创作名片未初始化时，只使用下列中立编辑底线：

- 只写已授权且可追溯的事实，不杜撰经历、情绪、身份或结果。
- 说清证据边界与不确定性，对产品缺点和反方处境保持诚实。
- 立场、口号、账号名、履历和商业承诺没有真源就不写。
- 第一人称只能承载当前素材明确记录的作者事实。

## 用户定制约束（必须优先遵循）

写作前必须先读取：

1. `brain/creative-library/profile.json` 中 `initialized: true` 的当前客户创作名片。
2. `brain/creative-library/rules.json` 中已启用的当前客户创作规则。
3. 当前 `run_id + slug` 的授权素材、confirmed blueprint 与风险边界。

不得读取其他项目、其他 run 或预置人物补齐身份。名片和当前素材冲突时，不代入冲突字段，标记 `review` 并要求用户确认。

### 上游完整性闸门

开始写正文前，必须确认 blueprint 至少包含以下信息：

- `0. 上游约束`：validate 路径、首发平台、必用素材证据、风险边界
- `1. 爆款拆解吸收`：参考样本、标题/钩子/叙事结构的可迁移机制
- `2. 核心判断`：本文反对什么、支持什么、重新解释什么
- `3. 目标读者与情绪入口`：读者处境、沉默解除、情绪入口
- `4. 公众号思想母版骨架`：正文结构和章节任务
- `5. 证据链与素材分配`：哪些证据进哪一段，哪些仍需保守表达
- `8. 评论区互动预埋`：置顶评论、首评、追评和高意向回复方向
- `9. 风险边界`：隐私、事实、标题承诺和商业承诺边界
- `10. 人工确认清单`：确认状态为 `confirmed` 或 `已确认`
- `11. 下一步执行指令`：确认本次进入 `/content-write`

如果缺少其中任一项，不生成正文，只输出缺口清单和补齐建议。

写作时必须继承上游约束：

- 必用证据必须进入正文，不得只写在自检块里。
- 爆款拆解与读者情绪入口必须进入写作任务卡、文章骨架和正文，不得只写在自检块里。
- 风险边界必须显式遵守，不能公开客户名、项目名、截图、价格、硬数字等未授权信息。
- 素材补充清单中仍缺失的内容，不能靠想象补。可以用保守表达，也可以在自检块里标记 `review`。
- 爆款对标只能借鉴机制，不要复刻文案，不要声称引用了不存在的样本或数据。
- 用户未指定文章风格时，必须按 `references/style-matrix.md` 自动推荐风格；用户指定风格时，也要检查该风格是否与证据完整度和风险边界匹配。

### 成稿交付契约

公众号成稿由两部分组成：

1. 可见正文：一篇正常可读的公众号文章，使用 H1 标题，不把正文写成报告。
2. 隐藏交付自检块：放在全文末尾，用 HTML 注释承载，供 runtime、audit、prelaunch 追溯。

写正文前必须先按 `references/style-matrix.md` 完成风格决策，再按 `references/longform-production.md` 完成三段式生产：写作任务卡、证据台账、文章骨架。它们不展示在正文里，但要以摘要形式写入隐藏自检块。

隐藏块格式固定如下：

```markdown
<!-- AIFIOS-WRITE-CHECK
上游 brief - pipeline/blueprint/...
选题立项结论 - ...
标题决策来源 - blueprint 标题假设：工作标题《...》；package 标题候选：主标题《...》
推荐风格 - 用户指定：无；系统推荐：business-insight（置信度：中）；最终采用：business-insight；理由：...
写作任务卡 - ...
证据台账 - ...
文章骨架 - ...
必用证据 - ...
传播心理兑现 - 沉默解除：...；满足动机：...；有效立场：...；传播入口：...；信念结构：...；受众情绪底层：...；受众还想听什么：...
风险边界 - ...
商业收口 - ...
母稿字数 - 3200-3800，最终以正文有效中文内容估算。
排版交接卡 - 封面字：...；摘要：...；HTML 排版：...；CTA：...；评论区首问：...
发布前待检查项 - ...
质检结论 - pass/review
-->
```

`质检结论` 只能写 `pass` 或 `review`：

- `pass`：上游证据已进入正文，硬数字有来源或保守处理，风险边界已避开，商业收口自然。
- `review`：仍缺真实案例、硬数字口径、客户授权、对标样本、传播心理正文兑现或作者一手判断，需要人工复核后发布。


以下三条是商业交付底线；当前客户已确认的更严格规则优先：

**1. 避免大量口语化**

保留口语节奏和自然人声，但克制口头禅密度。减少"说真的""我跟你说""这玩意""不是哥们"等高频口头禅的堆砌。口语化表达用于关键转场和情绪节点即可，不要每段都塞。目标是读起来像一个真诚、有思考力的人在说话——而不是话痨。

**2. 拒绝杜撰经历**

所有经历、场景、对话必须基于用户提供的真实素材。没有素材就不写。禁止编造"比如有一次...""我有一个朋友..."这类假设性例子。如果某个论点没有真实案例支撑，宁可坦诚承认"这块我还缺少一手观察"，也不要硬编。温度感来自真实细节，不是来自想象的细节。

**3. 保留真人感觉**

真人感不靠语气词堆出来，而靠：具体的场景描写、真实的数据支撑、坦诚的态度（承认不确定、承认局限）、有判断但不居高临下。文章要让读者感觉"这是一个真诚的人在认真思考"，而不是"这是一个AI在输出信息"。

用户可能给你任何形式的输入，产品brief、新闻链接、PDF、语音转文字、散乱想法、一段开头加几个要点。

**在创作名片、创作规则和当前 run 素材之后，可读取以下同客户历史记忆作为次级风格约束：**

1. `~/ai-content-system/brain/twin/content-dna.md` — 内容基因
2. `~/ai-content-system/brain/twin/voice-signature.md` — 声纹档案
3. `~/ai-content-system/brain/twin/pattern-library.md` — 模式库
4. `~/ai-content-system/brain/twin/reader-profile.md` — 读者画像孪生
5. `~/ai-content-system/brain/no-fly-zone.md` — 禁区清单

这些文件只能来自当前客户已发布内容的人工确认学习结果。文件为空、来源不明或与创作名片冲突时，不使用该项，回到 `style-adaptive.md` 的中立编辑基线。twin 不得提供姓名、账号、履历、公司或一手经历。

### 素材场景分类

收到输入后，先判断素材属于哪一类场景。不同场景对应不同的内容结构、标题逻辑和平台表达方式：

| 场景 | 核心用途 | 适合内容 | 主要平台 |
|------|---------|---------|---------|
| **个人履历 / 经验 / 知识分享** | 建立专业身份和可信背书 | 职业经历、方法论、行业判断、复盘 | 小红书、公众号 |
| **访谈 / 嘉宾出席 / 演讲分享** | 将线下高价值对话沉淀为内容资产 | 活动纪实、观点金句、人物背书 | 公众号、小红书 |
| **个人成长 / 人生心得** | 增强真实感和情绪连接 | 转折、选择、压力、修复、长期主义 | 小红书、公众号 |
| **日常工作 / 生活记录** | 将碎片化日常变成稳定素材池 | 出差、会议、客户拜访、工作现场 | 小红书、公众号 |
| **业务 / 产品增长 / 引流获客** | 把内容转化为商业信任入口 | 客户案例、产品价值、服务说明、转化 CTA | 公众号、小红书 |
| **全球化表达 / 跨境内容** | 面向海外用户、东南亚华人和关注中国市场的专业人士 | 双语内容适配 | TikTok、Twitter/X、小红书 |

如果用户没有明确说场景，根据素材内容反推并确认；如果素材跨多个场景，以**主场景**为准，其他场景作为补充素材。

**先吃透素材，再判断选题质量。**

一个好选题要通过HKR质检：
- **H (Happy)** 足够有趣、有悬念吗？标题和开头能让人好奇想点开吗？
- **K (Knowledge)** 有信息量吗？看完能学到新东西吗？
- **R (Resonance)** 能戳中情绪吗？让人"对对对我也这么想"？

S级选题三项兼备，及格选题至少占两项。如果素材的选题方向明显只占一项或一项都没有，主动跟用户沟通调整方向。

如果素材信息不够（只有一个主题没有具体要点），主动问用户要更多信息，"你大概想讲哪几个点？有没有什么自己的经历想放进去？有没有什么让你特别兴奋或者特别想吐槽的地方？"

## 第二步：明确AI的角色边界

这一步非常重要。这个skill是一个文风生成器，不是替代你思考的工具。AI最大的价值不是生成内容，而是提供素材和启发。

### AI擅长做的（放心交给AI）

**找证据和佐证**：给出一个观点后，让AI在历史、学术、文化中找到能支撑（和反驳）这个观点的论据。比如你想表达"信息差是亘古不变的"，AI可以帮你找到《北京折叠》、赛博朋克的"High Tech, Low Life"、1880年代电力普及的历史等素材。

**找类比和比喻**：当你需要一个生动的比喻来解释一个抽象概念时，AI可以提供多个候选。比如"AI像一个全能实习生"这种类比，你自己脑子里有就直接给AI让它按这个写，没有的话可以让AI提供几个候选让你挑。

**按确定的角度扩写**：当你已经想好了核心角度和每段的标题，AI可以帮你填充论述和细节。比如你已经确定了"信息被折叠成三层"这个角度，并且写好了每层的标题，AI来负责扩写每层的内容。

**补充学科背景知识**：格式塔心理学、荣格阴影理论、因果语言模型原理这些，AI可以帮你准确表述。

**梳理逻辑和结构建议**：写到一半不确定某一段放哪最好，或者觉得逻辑不够流畅，AI可以帮你调整。

### AI做了会暴露的（必须人来）

**第一手观察和真实经历**：买9.9的DeepSeek、花499找人上门装OpenClaw、凌晨三点偷偷起床去网吧。这些不可能用AI编造，一编就假。

**核心创意角度**：从"淘宝卖DeepSeek"联想到"北京折叠"、从"AI看不到爱心"推导出"我们活在流中而AI活在帧中"。这种让文章真正立住的创意灵感，AI给不了。AI可以提供很多候选，但最终那个"对，就是这个！"的判断必须是你自己的。

**情绪的真实表达**：用"我当时就愣住了"而不是"我当时很震撼"。前者是体感记忆，后者是知识性描述。AI容易写后者。

**数据到人物的同理心转换**：从"1000个已付款"想象出那个四五线城市刚毕业的学生的完整人生，这种温度是需要作者真心去感受的。

### 理想的协作流程

```
人：提供素材 + 核心观点 + 个人经历 + 情绪节点
 ↓
AI：补充背景知识 + 找证据类比 + 结构建议 + 按角度扩写
 ↓
人：二次改写（加入自己的声音、打破节奏、补充真实细节）
 ↓
AI：按四层自检体系检查 → 输出修改建议
 ↓
人：终审和定稿
```

## 第三步：写作

### 文章原型

公众号长文可以归为五种常用原型，写之前先判断属于哪种，每种的写法重心不同：

文章原型不是可选风格。风格模式来自 `references/style-matrix.md`，回答“这篇文章应该用什么表达任务承载”；文章原型回答“局部段落怎么推进”。写作任务卡里两者都要记录。

**调查实验型**：亲自下场去做一件事，然后报道发现。买9.9的DeepSeek、亲手给AI投毒、花499找人上门装OpenClaw。核心是"我替你去做了这件事"。写法重心在过程叙事和发现的层层递进。

**产品体验型**：拿到产品实际使用，带着读者一起体验。miclaw手机Agent、Seedance 2.0。核心是"跟我一起玩"。写法重心在场景演示和真实感受。

**现象解读型**：观察到一个现象，然后层层深入分析。三宫格图片刷屏、AI看不到爱心、复制粘贴Prompt。核心是"你注意到了吗？背后是什么？"。写法重心在观察→好奇→研究→哲学升维。

**工具分享型**：分享一个实用的工具/Prompt，但用个人故事包裹。天赋挖掘Prompt。核心是"我发现了一个好东西"。写法重心在个人故事铺垫→工具展示→效果惊艳。

**方法论分享型**：把自己长期积累的经验和方法论系统性地分享出来。"如何找回你的创造力""用AI三年的9条心得"。核心是"我把压箱底的东西掏给你了"。写法重心在每一节都必须有可执行的行动建议，同时必须坦诚地提到学习成本、时间曲线和常见失败点（"一开始可能会有点笨拙，花的时间比手动做还长"），而不是只画饼。开头要用谦逊铺垫卸掉傲慢感（"我也不知道行不行""不成熟的经验"），结尾要回扣所有行动点并升华。

### 结构模板

一篇典型的公众号长文可按这样组织：

```
【开头】感性切入，从一个具体事件/场景开始，迅速建立情绪
  ↓
【背景铺垫】简要科普，让非专业读者也能看懂，但科普方式是聊天式的
  ↓
【核心内容】分几个板块展开，每个板块有：
  - 一个明确观点
  - 至少一个具体场景/人物/对话支撑
  - 私人视角的连接（"我自己也是这样"）
  - 一句扣主线的话，把偏出去的内容拉回来
  ↓
【升华】从具体事件拉到更大的文化/哲学/历史参照物
         不是论文式总结，更像是"聊着聊着自然想到了"
  ↓
【收尾】几种常见收法，选最合适的一种：
  - 引用收尾：用别人的一句话作结（"比比说：磨平一些信息差"）
  - 哲思余韵：一个短句留白（"时间。流逝的本身。"）
  - 行动呼吁：鼓励读者去做一件事
  - 信念宣言：表达对未来的坚信
  - 回环呼应：回到开头的意象，但视角已经不同
  ↓
【结尾与署名】
根据 confirmed blueprint 的商业收口和互动预埋自然收尾。不默认追加点赞、星标、转发口播或作者行。只有创作名片明确提供创作者名称，且当前稿件已确认需要署名时，才输出署名。
```

### 长文判断链蓝图

写公众号长文时，不要把 `content-blueprint` 机械扩写成段落。真正的长文交付必须完成一条判断链：

```
题眼 → 读者处境 → 真实证据 → 核心判断 → 反方理解 → 方法/启发 → 商业收口
```

每一环的最低要求：

- **题眼**：一句话说清这篇文章到底在反对什么、支持什么、重新解释什么。不能只是主题名。
- **读者处境**：先替目标读者说出他为什么会卡住、焦虑、好奇或误判。读者要能感觉“这说的是我”。
- **真实证据**：至少使用 2 类证据，来自上游 brief 的一手素材、具体场景、用户原话、公开来源、对标样本或作者已验证体验。缺证据就写 `review`，不能编。
- **核心判断**：给出明确立场，不要只做信息搬运。判断必须能被一句话复述。
- **反方理解**：至少承认一次对立面或普通读者为什么会那么想，避免文章变成单向说教。
- **方法/启发**：读者看完要带走一个可执行动作、判断标准或观察框架。
- **商业收口**：结尾自然指出下一步关系，不硬卖，也不完全散掉。可以是评论、私信、复盘、诊断、产品/服务入口。

写作前先在心里完成这张表：

| 环节 | 本文答案 | 证据来源 | 风险 |
|---|---|---|---|
| 题眼 | ... | blueprint 核心判断/标题方向 | 是否太平 |
| 读者处境 | ... | intake/validate/评论需求 | 是否泛泛 |
| 真实证据 | ... | 素材/公开来源/对标 | 是否缺授权/缺口径 |
| 核心判断 | ... | blueprint 核心判断 | 是否无判断 |
| 反方理解 | ... | 读者画像/客户处境 | 是否说教 |
| 方法/启发 | ... | 作者经验/案例复盘 | 是否空泛 |
| 商业收口 | ... | 产品/服务/下一步动作 | 是否硬卖 |

这张表不要放进正文，但要反映在文章结构里。隐藏自检块里的 `必用证据`、`传播心理兑现` 和 `商业收口` 必须能在正文中找到对应内容。

### 传播心理兑现蓝图

`content-blueprint` 的 `## 3. 目标读者与情绪入口` 和 `## 8. 评论区互动预埋` 不是参考背景，而是公众号长文的写作约束。写正文前必须把它转成一条可读的心理推进线：

```
沉默解除开头 → 真实案例承接 → 信念冲突展开 → 方法论解决 → 商业收口
```

最低要求：

- **沉默解除开头**：开头先说出读者不太愿意承认、但真实存在的隐秘情绪或处境。
- **真实案例承接**：用上游证据承接情绪，不用虚构故事制造共鸣。
- **信念冲突展开**：明确本文确认了读者什么信念，又挑战了读者什么行为。
- **方法论解决**：给出一个可执行判断标准或行动，而不是只安慰读者。
- **商业收口**：顺着读者还想听什么，给出评论、私信、诊断、模板或下一篇选题的轻动作。

正文必须能看见以下 5 件事：

1. 受众没有说出口的情绪
2. 作者站在哪一边
3. 本文确认了什么信念
4. 本文挑战了什么行为
5. 读者看完后还想继续追问什么

这部分不要写成报告。它应该自然变成开头、转场、冲突、方法和结尾，而不是独立小标题。隐藏自检块里的 `传播心理兑现` 必须逐项说明如何兑现。

### 字数和格式

- 公众号思想母版一般在 3000-4000 字
- 段落要短，很多时候一句话就是一段
- 重要观点前后留白，让它"呼吸"
- 科普/解释部分可以稍长，但也要保持聊天感
- 需要插图的位置标注"图片"即可
- **不加小标题**。绝大多数文章从头到尾一口气顺下来，不需要任何小标题来切割。板块之间用口语化转场句自然衔接（"说到这个""回到xxx这块""顺着上面的再聊聊"）。只有"N条心得"这种分条目结构才用数字编号，也不是正式标题

## 第四步：四层自检体系

写完后必须跑完整个四层质检流程。这个自检体系的设计理念来自软件工程中的测试金字塔，从最基础的硬性规则到最主观的活人感判断，层层递进。每一层都有明确的通过标准和修复指引。只有四层全部通过，文章才算达标。

### L1 硬性规则检查（自动扫描层）

这一层检查的是绝对不能违反的规则，类似代码的语法检查。任何一项不通过就必须修复，没有例外。

**L1-1 禁用词扫描**
全文搜索以下词汇，出现则必须替换：
- "说白了" → 换成"坦率的讲"、"其实就是"
- "意味着什么" / "这意味着" → 换成"那结果会怎样呢"、"所以呢"
- "本质上" → 换成"说到底"、"其实"
- "换句话说" → 换成"你想想看"、"也就是说"
- "不可否认" → 直接删掉，换成正面陈述
- "综上所述" / "总的来说" → 换成具体的回扣句
- "首先...其次...最后" → 用自然的转场词替代
- "值得注意的是" / "不难发现" → 删掉，直接说

**L1-2 禁用标点扫描**
全文搜索以下标点，出现则必须替换：
- 冒号"：" → 用逗号替代
- 破折号"——" → 用逗号或句号替代
- 双引号""或"" → 用「」替代，或直接不加引号

**L1-3 结构性套话扫描**
检查是否出现以下模式：
- "让我们来看看..." / "接下来让我们..."
- "在当今...的时代" / "随着...的发展"
- 连续使用bullet point罗列观点（超过3个就需要改成散文叙述）
- 大段加粗（超过2行的加粗几乎肯定是过度结构化）

**L1-4 工具名检查**
确认所有提到的AI工具/产品都使用了具体名称，没有出现"AI工具""某个模型""相关技术"等空泛表述。

**通过标准**：以上四项扫描零命中。
**修复方式**：逐个替换，用推荐口语化词组中的表达替代。

### L2 风格一致性检查（模式匹配层）

这一层检查文章是否符合当前客户创作名片、已启用创作规则和经人工确认的 `brain/twin/` 风格约束。

**L2-0 Twin 约束检查**
- 是否违反 `brain/no-fly-zone.md` 中的禁区？
- 是否与 `voice-signature.md` 中的标志性句式/标点/节奏冲突？
- 是否与 `reader-profile.md` 中的读者画像匹配？（用词、案例、焦虑点）
- 是否复用了 `pattern-library.md` 中已验证有效的模式？

**L2-1 开头检查**
- 是否从一个具体的、当下的事件/场景切入？（不是宏大叙事）
- 第一句话是否让读者产生"然后呢？"的冲动？
- 有没有使用任何教科书式开头？

**L2-2 节奏与结构检查**
- 是否有长短句交替？（连续3句以上句式长度相近 = 节奏呆板）
- 是否有一句话独立成段的"断裂"效果？（全文至少出现3次）
- 偏离主线的段落后面是否有"扣主线句"拉回来？
- 有没有用疑问句来制造节奏的刹车和转向？
- 是否避免了不必要的小标题？（除非是分条目的方法论文章，否则不应出现markdown标题或加粗小标题，靠口语化转场自然衔接）

**L2-3 口语化检查**
- 是否使用了推荐口语化词组？（全文出现4-6个不同的口语化表达即可，受「避免大量口语化」约束，不要堆砌）
- 有没有论述中的故意打破？（重复强调、中途打断、省略主语等）
- 有没有至少一处自嘲或承认不足？
- 标点是否用来表达情绪？（"。。。""？？？""= ="至少出现其中一种）

**L2-4 标点禁令二次确认**
- 全文是否完全没有冒号、破折号和双引号？（AI容易在修改过程中重新引入这些标点，需要二次确认）

**通过标准**：L2-1全部通过，L2-2至少3/4通过，L2-3至少3/4通过，L2-4通过。
**修复方式**：逐段检查，对不符合的段落进行改写。重点关注那些"读起来像在写报告"的段落。

### L3 内容质量检查（深度审查层）

这一层检查内容本身的深度和说服力，类似代码的集成测试。

**L3-1 观点支撑检查**
- 每个核心观点是否都有具体的人/场景/细节/数据支撑？
- 有没有空泛的观点只有论断没有例证？
- 是否至少使用 2 类证据：一手素材、用户原话、公开来源、对标样本、作者已验证体验？
- 隐藏自检块里的必用证据，是否都进入了正文？

**L3-2 知识输出方式检查**
- 知识点是否以"聊着聊着顺手掏出来"的方式呈现？
- 有没有出现"下面我来介绍""首先需要了解"这种教科书式科普？
- 引用（论文、书籍、历史）是否自然融入论述，像"聊着聊着想起来的"而不是"我特意去查的"？

**L3-3 文化升维检查**
- 有没有至少一处从具体事件连接到更大的文化/哲学/历史参照物？
- 这个连接是否自然？

**L3-4 对立面与同理心检查**
- 在讲核心观点时，是否有对对方立场的理解和承认？
- 有没有先站到读者的处境里，再给出自己的视角？
- 有没有把反方讲成一个真实处境，而不是一句“他们错了”？
- 有没有兑现上游 `目标读者与情绪入口` 和 `评论区互动预埋`，让沉默解除、满足动机、有效立场、信念冲突和后续需求进入正文？

**L3-5 判断链完整性检查**
- 题眼是否足够清楚，读者能不能一句话复述本文在讲什么？
- 读者处境是否具体，而不是泛泛写“很多人都会这样”？
- 核心判断是否明确，还是只做资料搬运？
- 方法/启发是否能落到一个今天就能执行的动作或判断标准？
- 商业收口是否自然，既不硬卖，也不消失？

**L3-6 文章类型专项检查**
根据文章原型做针对性检查：
- 调查实验型 → 有没有"亲自下场"的叙事感？过程是否有层层递进的发现？
- 产品体验型 → 有没有真实的使用场景？有没有跟其他产品的自然对比？
- 现象解读型 → 是否有"观察→好奇→研究→升维"的推进？
- 工具分享型 → 有没有个人故事铺垫？效果展示是否让人"卧槽"？
- 方法论分享型 → 每节是否都落到了可执行行动？是否坦诚说明了学习成本和失败点？有没有谦逊铺垫？

**L3-7 逐一展示检查**
- 如果涉及多个产品/案例的比较，是不是用了逐一展示（每个带吐槽点评）而不是一次性罗列？

**通过标准**：L3-1、L3-2、L3-5必须全部通过，L3-3至L3-7中至少通过相关项（根据文章类型，有些项目可能不适用则跳过）。
**修复方式**：需要重新审视不通过的段落，补充案例、改写知识输出方式、或调整文化升维的自然度。

### L4 活人感终审（最终人格层）

这是最重要也是最主观的一层。这一层不是逐项检查，而是以读者的视角通读全文，回答一个核心问题：

**"读完这篇文章，我感觉是一个有见识的普通人在认真跟我聊一件打动他的事，还是一个AI在给我输出信息？"**

具体的感知维度：

**L4-1 温度感**
- 文中的情绪表达是体感记忆（"我当时就愣住了""鼻子一酸"）还是知识性描述（"我感到非常震撼"）？
- 如果有人物描写，这个人物是否让你"能感觉到他的体温"？

**L4-2 独特性**
- 这篇文章的角度是否能在当前客户的创作名片和授权素材中找到证据？
- 还是换一个AI博主也能写出差不多的东西？

**L4-3 姿态检查**
- 文章的语气是不是"一个有见识的普通人在认真聊一件打动他的事"？
- 有没有不自觉地滑入了"导师在教学生"或"品牌在做营销"的姿态？

**L4-4 心流检查**
- 从头到尾读，有没有哪个地方你的注意力断掉了？需要回头理解逻辑？
- 如果有，那个地方就是需要修复的节奏问题。

**通过标准**：L4-1到L4-4整体感觉"这像是真人写的"。如果任何一项让你觉得"这段AI味太重了"，就需要返工。
**修复方式**：这一层没有机械的修复方法。把「AI 味重」的段落找出来，对照当前客户已确认的原话、行文风格和表达偏好重写。没有客户语料时只做中立编辑，不想象客户「会怎么说」。

### 自检输出格式

完成四层自检后，先在内部形成简洁质检报告。除非用户明确要求展示，不要把完整质检报告放进公众号正文。最终成稿只在末尾保留 `AIFIOS-WRITE-CHECK` 隐藏块。

内部质检报告格式：

```

- 结构套话：X处命中（已修复/待修复）
```
