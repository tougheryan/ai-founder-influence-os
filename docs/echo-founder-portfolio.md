# Echo Founder：求职展示与商用收敛

更新于 2026-10-11。当前产品版本以根目录 `VERSION` 为准。本页用于讲解已有实现和安排下一步验收，不改变 [RELEASE.md](../RELEASE.md) 的发布要求。

## 30 秒介绍

Echo Founder 帮助需要持续输出内容的创始人，把自己的素材整理成适合公众号、小红书和视频号的内容，并保留审稿、修改、排版、交付和发布记录。重点是让作者掌握事实和表达，拿到能继续使用的成品。

目前已有本地运行的桌面产品与源码验证。展示使用明确标注的虚构样例，证明工作流和交付行为；真实本地模型稿经人工修改已完成复制、下载与重开恢复；无人干预质量、实际费用与客户安装包仍待验收，尚不能宣称正式商用或已获得付费客户。

## 五分钟讲解顺序

| 时间 | 展示什么 | 讲清什么 |
| --- | --- | --- |
| 0:00–0:40 | 一份素材为什么要分别交付图文和口播 | 目标用户、重复工作，以及为什么单次聊天输出还需要编辑和交付管理。目标用户与付费意愿仍是待验证假设。 |
| 0:40–1:20 | 七步流程：素材 → 方案 → 正文 → 排版 → 成品 → 发布记录 → 复盘 | 已有题目可走作者素材路径，不必先购买研究服务；方案和正文仍需要可用模型连接。作者确认贯穿流程。 |
| 1:20–2:30 | 成品页，先小红书、再视频号 | 小红书标题、正文与标签分开复制；视频号只复制需要朗读的句子，拍摄提示另行展开。展示实际下载的 Markdown 文件。 |
| 2:30–3:20 | 修改前后对照、过期原稿拦截 | 从“生成了一段文字”走到“交付正确版本的完整成品”。先展示用户遇到的混排问题，再讲对应修复。 |
| 3:20–4:20 | 产品或工程视角的取舍 | 产品面试讲付费价值与范围收敛；工程面试讲状态恢复、版本绑定、主进程权威校验和异常处理。 |
| 4:20–5:00 | 下一轮真实试用与验收条件 | 用真实首篇、修改时间、实际费用和是否愿意再次使用验证价值；不以测试数量代替商业成果。 |

本次离线展示页：`outputs/job-showcase-20261010/index.html`。页面内嵌真实截图与下载样例，可直接打开，不依赖模型连接或本机开发服务。它是产品讲解页，不是可操作的完整产品。分享前仍需本人核对个人贡献和对外表述。

本机桌面演示入口为 `outputs/desktop-showcase-20261010/打开 Echo Founder 演示.command`。它使用独立的 `demo-project` 和 `desktop-user-data-20261011`，仅含“客户临时加需求，先确认范围（虚构验收）”一份草稿，不继承模型环境凭据。10 月 11 日已更新到经过源码摘要核对的当前构建，重新通过版本显示、复制、实际下载、退出重开与重复启动验证。原稿与图片未改，旧方案补齐平台章节后另存并重新核对。

真实本地模型试验桌面使用另一份独立项目，记录在 `outputs/approved-14-17-20261011/desktop-session.json`。首页按用户要求恢复为原版“让创始人的一个观点，生长为全球影响力。”；用户已同意的平台范围核对、完整方案局部修改和任务状态恢复均已实施。记录见 `outputs/approved-fixes-20261011/封面恢复与三项修复复验.md`。这些操作验收不代表模型成稿质量或真实客户采用。

第17项已按用户批准实施：方案变更后，逐页核对并沿用原图文，再通过正常排版确认进入成品页。原生界面复验未调用图片生成，也未用后台接口绕过；原正文与32张历史图片字节不变。见 `outputs/approved-14-17-20261011/visual-reconfirmation-proof.json`。

这份入口依赖本机仓库、Electron 和已验证的独立界面构建，是源码演示，不是可分发安装包。它会在界面源码或构建编号变化时拒绝继续打开旧构建；重新构建和复验后再更新启动记录。桌面服务使用动态本地端口，不应收藏它的地址。旧的浏览器体验服务 `http://127.0.0.1:63972/production` 仍属于另一份隔离项目，不能与桌面样例的编辑状态混用。其他电脑展示时使用上面的离线讲解页。

无云模型账号的本地验收已运行：`outputs/local-model-20261010/` 的固定版本 Qwen 权重已通过校验，原生桌面连接测试成功。首次方案请求耗时 93.963 秒，返回 5,176 tokens，但只选视频号却生成小红书结构，并出现来源含义偏差；当时产品检查误判通过，人工审阅未通过。10 月 11 日完成用户批准的平台范围检查、完整方案局部编辑与任务状态修复，恢复原版首页，并在隔离项目中手动修正、重新确认方案。原始错误版本保留。同一轮素材事实仍有人工补回，不计作自动识别成功。

随后真实生成正文用时 44.468 秒，定向修改用时 15.596 秒。字段采用标题加下一行值的格式，产品未识别标题、钩子和时长；发布字段也未完整标明。口播初稿 204 字符、修改后 196 字符，低于 250–350 的要求，均未以要求的具体问题收尾。局部修改因其他字段尚未通过整稿检查而不能采用。原生桌面已实际下载保留的完整失败稿并核对字节；刷新可找回原稿及未采用候选，未新增模型请求。这些是修复前记录，原件保留在 `outputs/body-trial-20261011/`。当前14–17已批准并实施。

人工补充方案后的真实复试用时58.061秒，得到317字符口播，但平台代码、人称、结尾与事实表达仍有偏差。用户批准14–17后，产品统一字段解释、增加待完成稿逐步保存和本篇要求核对。操作者通过界面七次手动保存，得到311字符口播；确认正文后实际复制、下载并退出重开，原生剪贴板逐字一致、下载逐字节一致。没有新增模型调用；原始Qwen稿保留。见 `outputs/approved-14-17-20261011/14-17实施与桌面复验.md`。

离线讲解页保留手写虚构交付样例，并单独披露真实模型失败、人工修正与最终交付证据，两者不混为同一次自动生成。本机演示入口已更新到最终构建并重新通过剪贴板、下载与重开验证。

下一项有效进展是观察真实用户是否采用成品、修改花费多久、是否愿意继续使用，并按发布门禁完成安装交付；不以本地人工辅助样例代替这些证据。

现场执行使用[首篇真人试用任务与记录表](first-user-trial.md)。此前“人工修正”描述的是产品的手动编辑功能：七次保存实际由 Codex 通过自动化脚本操作界面完成，并非七次真人客户编辑。当前没有真人编辑用时，不能将自动化运行时长换算为节省工时。
