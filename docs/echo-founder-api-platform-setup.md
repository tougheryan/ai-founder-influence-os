# Echo Founder API、研究与平台桥配置

本说明适用于 Echo Founder `0.2.0-beta.2` 内部测试版。所有账号必须由客户本人或获授权的操作者提供；不要在聊天、截图、日志或诊断包中传递真实密钥。

## 凭据保存规则

桌面端通过 macOS 钥匙串支持的加密存储保存模型、TikOmni 与平台桥凭据。页面只能执行“状态、保存、删除”，不会读取或回显原始密钥。

- 从旧版本升级时，应用会尝试迁移旧的明文模型 Key 与 TikOmni Token；只有加密保存验证成功后才删除明文字段。
- 修改凭据后，桌面端会在有限时间内重启本地服务并执行健康检查。
- 项目备份不包含任何密钥、Cookie、账号会话或钥匙串数据。
- 换电脑或从备份恢复后，必须重新配置全部凭据与平台登录状态。

内部文件、环境变量和 IPC 类型仍可能使用 `AIFIOS`/`aifios` 前缀，这是历史兼容标识，不是客户产品名。

## 模型 API

1. 打开“设置 → API 连接向导”。
2. 选择服务商与模型。
3. 填入 API Key，保存后点击“测试连接”。
4. 测试通过后退出并重开应用，确认状态仍为“已保存”或“系统钥匙串”。

模型服务商、可用模型、额度、限流和内容政策由客户与服务商确认。连接失败时依次检查：Key 是否有效、账户是否有额度、模型名是否有权限、网络是否允许访问对应 API。不要把密钥复制到项目文件中作为绕过方式。

## TikOmni 实时研究

1. 打开“设置 → 研究服务”。
2. 保存 TikOmni 访问凭据并测试连接。
3. 在内容生产阶段 2 发起真实研究。

阶段 2 按本次已选平台分别检查实时证据。某个 lane 不可用时只阻断该 lane，并明确显示“对标样本不足”；不会用历史样本或模型推断伪装成功，也不会把缺指标样本称为爆款：

- Token 缺失、无效或额度不足；
- 当前已选平台不可用；
- 返回结构不符合契约；
- 证据数量或可追溯字段不足；
- 实时快照与当前 `run_id + slug` 不一致。

原始研究结果可能保留在项目目录中作为本次 run 的冻结证据；项目备份可迁移这些项目数据，但不会迁移 Token。

## 公众号

优先使用公众号官方草稿 API。设置中填写客户自己的 AppID、AppSecret 及可选作者，点击「保存接口」后可刷新本机保存状态。本版设置页不提供独立的公众号连接测试或草稿测试按钮；不要把「已保存」视为平台接口已通过。

首次真实校验发生在当前 run 的内容、视觉和草稿审批都通过后：用户在发布台对当前公众号任务执行「填入草稿」，系统只尝试创建本次草稿，不会公开发送。接口失败时任务保留明确错误，可在已配置且已授权的情况下降级到公众号浏览器编辑器。

浏览器降级只负责填入标题、正文和素材。先在「长文平台的本机已登录浏览器」保存编辑器地址，再点击「打开登录」由操作者完成授权。遇到登录失效、验证码、风控或完成状态未知时立即停止并交给人工。Echo Founder 永不点击公开发送。

## 小红书

小红书使用隔离的持久浏览器会话填入标题、正文和图片：

1. 在设置中启用小红书浏览器桥。
2. 在打开的浏览器会话中由操作者本人完成登录与设备确认。
3. 从草稿台执行填入，核对标题、正文和视觉版本。
4. 由操作者在平台页面中手动发布。

登录失效、验证码、风控、设备确认或页面结构不匹配时，任务保持待人工状态，不会无限重试或报告虚假成功。

## 视频号

视频号 lane 独立生成一套开场钩子、口播稿、镜头提示、字幕重点和发布文案，不从公众号文章改写，也不创建静态视觉任务。本期不生成或代发成片；操作者使用该执行稿完成拍摄、剪辑、填入草稿和人工发布。

## 发布凭证与数据回流

草稿队列严格跟随本次平台选择，每个已选平台一项；三平台全选时为公众号、小红书、视频号各一项。系统把“已填入草稿”和“已公开发布”分开记录。

用户公开发布后，必须勾选确认，并提供公开 URL 或带内容/视觉哈希的本地凭证。指标不全时保持“待补”；只有人工确认后的真实指标才会进入周复盘和长期学习。任何凭证都必须绑定本次 run 的草稿 payload、内容哈希与视觉哈希，避免旧版本数据回流到新版本内容。
