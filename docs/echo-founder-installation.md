# Echo Founder 0.2.0-beta.2 安装与首次启动

本说明只适用于内部测试产物 `Echo-Founder-0.2.0-beta.2-mac-arm64.dmg`。

## 交付边界

- 系统要求：macOS 13 Ventura 或更高版本。
- 处理器：Apple 芯片（M 系列，arm64）。Intel Mac 与 Windows 不在本期支持范围内。
- 安装包内置 Electron、Node.js、Python、Chromium 与内容运行时。客户电脑无需预装 Node.js、Python、Homebrew、Codex 或项目源码。
- 生成方案和文章需要客户自行准备模型 API；选择“帮我找方向”时才需要 TikOmni 研究服务。平台账号只按实际发布需要准备，对应服务费用由客户承担。
- 本版没有 Apple Developer ID 签名、公证与 staple，只能作为内部测试版分发。首次启动可能需要手动确认；不要关闭 Gatekeeper。
- Echo Founder 不会自动点击任何平台的公开发送按钮，也不承诺平台审核、流量或经营结果。

新安装默认把项目放在当前用户主目录下的 `Echo Founder/`。若升级机器已经保存过旧项目选择、显式配置了 `AIFIOS_PROJECT`，或只存在历史默认目录 `ai-content-system/`，应用会继续使用该目录，不会为了改名移动或覆盖既有项目。

`AIFI-OS`、`AIFIOS_*` 和 `aifios.*` 只是在内部路径、环境变量与历史数据 schema 中保留的兼容名称；客户看到的应用名、DMG、诊断包与交付文档均为 Echo Founder。

## 验收安装包

交付方应同时提供：

- `Echo-Founder-0.2.0-beta.2-mac-arm64.dmg`
- `Echo-Founder-0.2.0-beta.2-mac-arm64.manifest.json`
- `Echo-Founder-0.2.0-beta.2-mac-arm64.package-manifest.json`
- `Echo-Founder-0.2.0-beta.2-mac-arm64.dmg.sha256`

不要安装来源不明、文件名或版本不一致的包。若需要自行核对摘要，在“终端”中运行：

```bash
shasum -a 256 Echo-Founder-0.2.0-beta.2-mac-arm64.dmg
```

输出应与 `.dmg.sha256` 和交付清单中的 `sha256` 完全一致。DMG manifest 中的 `package_manifest.sha256` 还必须与 `Echo-Founder-0.2.0-beta.2-mac-arm64.package-manifest.json` 一致；后者如实记录 baseline/current Git SHA、`dirty` 状态、shipped runtime 摘要和随包依赖/许可证 inventory。正式交付记录要求 `dirty=false`。这些摘要只证明构建与传输链可追溯，不代表安装包已经通过 Apple 签名或公证。

## 安装

1. 双击 DMG。
2. 将 `Echo Founder.app` 拖入“应用程序”。
3. 在 Finder 的“应用程序”中找到 Echo Founder。
4. 首次启动时，按住 `Control` 点击应用，选择“打开”，再在系统弹窗中确认。
5. 后续可正常双击启动。若系统仍然拒绝，停止操作并联系交付方核对文件摘要；不要运行关闭 Gatekeeper 或移除安全属性的终端命令。

## 首次配置

首次建议只做一个平台。有自己的题目时，选“按我的题目写”；需要研究公开参考再选题时，选“帮我找方向”。先在工作台添加、整理文字素材也可以，不必提前申请所有服务账号。

1. 生成方案和文章前，进入“系统设置”→“连接写作服务”，选择服务商并填写 API Key；没有密钥时展开账号准备指引。点击“保存设置”，再“测试连接”。保存不调用模型；测试会发送一次短文本请求，可能计费。成功只说明当次请求返回，不代表余额充足或文章质量已验收。
2. **按我的题目写**：不需要配置 TikOmni，也不需要补做平台研究。核对素材、题目和本次所选平台后即可准备方案，生成仍使用已配置的模型服务。
3. **帮我找方向**：再配置 TikOmni 研究凭据并测试。只研究本次已选平台；失败的平台不会被历史样本冒充实时结果，也不会要求补齐未选平台。
4. 到发布准备环节，需要应用填入平台草稿时，再配置对应平台授权；首次生成文章不要求先授权三个平台。也可先检查本机成品，再由本人到平台手动发布。视频号交付口播与拍摄执行稿，不生成静态视觉或成片。
5. 本次包含公众号时，在工作台选择排版样式；公众号优先使用本机 md2wechat，不可用时回退内置排版。小红书在本机渲染 P1–P8。当前版本不需要生图账户。

重新打开应用后，检查本次实际配置过的服务是否仍显示已保存。系统不会回显原始密钥。“已配置”不是实时连接或额度保证，问题仍需结合连接结果与服务商账单核对。

详细字段和降级规则见 [API、研究与平台桥配置](echo-founder-api-platform-setup.md)。

## 第一次完成一篇内容

下面以“已有题目，只写一篇公众号文章”为例。首篇不要求完成三个平台，也不要求先做账号对标或周复盘。

1. 从侧栏“本期内容生产”进入工作台，在“粘贴文字”中放入一份已获授权的笔记或案例，点击“整理素材”，核对事实、写作要求和公开限制。
2. 只选择“公众号”，选“按我的题目写”，核对或填写“这期想写什么”。当前源码会为尚未主动选择方式的新稿带入粘贴素材中唯一明确的作者题目，不自动生成。缺模型连接时，点“保存草稿并连接写作服务”，完成设置后用“回到工作台继续”返回原稿；再点击“确认素材，按这个题目写”。安装包是否具备以上引导，以实际交付版本为准。
3. 核对题目、读者、结构、结尾和排版样式，确认写作方案，再生成并审阅文章。需要改动时先修改、比较、确认当前版本。
4. 检查公众号完整排版和发布成品，核对拿到的文章是否完整、可读、保留所需说明；未选的小红书和视频号不需要补做。
5. 要发布时，再使用已授权的平台草稿连接或手动处理成品，由本人在平台检查并公开发送。准备草稿不等于已发布；真实发布后再登记链接或凭证，周复盘可后补。

如选择“帮我找方向”，第 2 步改为配置研究服务、点击“确认底稿并开始找选题”，再核对所选平台的参考与建议题目。研究失败应处理相应提示；改为按自己的题目写需要明确选择并重新确认素材依据。

## 交付方的完整验收

以下是交付方在专用验收项目中执行的检查，不是客户首篇的必做清单：

1. 在实际交付的安装包中分别验证“按我的题目写”和“帮我找方向”，覆盖单平台及多平台选择，确认未选平台不阻断当前任务。
2. 分别核对三个平台的产物：公众号完整文章与 HTML、小红书 P1–P8、视频号口播与拍摄执行稿。多选时共享事实，各平台独立组织内容；视频号不生成静态视觉。
3. 采用本次需要的排版后，检查草稿队列与平台选择一致，每个平台一项。只向已授权测试账号填入草稿；验证码、风控或设备确认出现时转人工处理，不自动公开发送。
4. 用户确实手动发布后，再验证真实链接或本地凭证登记、真实指标补录和人工确认复盘。未实际发布的项目保留未验收状态。
5. 导出项目备份，在新的项目目录中恢复；恢复后重新配置凭据。

本文按当前源码的上手流程修订，不证明既有安装包已包含这些改进。交付方须提供对应安装包的实测记录与随包帮助；源码检查通过不等于真实账号验收通过，也不表示已重新打包或正式发布。

## 故障与诊断

在“设置”中下载脱敏诊断包，并记录：应用版本、macOS 版本、发生阶段、操作时间和可复现步骤。诊断包不应包含 API Key、Token、Cookie、原始授权头或完整本地路径。

不要向交付方发送 API Key、TikOmni Token、浏览器 Cookie、完整私人素材或聊天记录。若诊断包中意外出现这些内容，应停止发送并报告安全问题。

商业能力现状与明确阻断项，以交付方随安装包单独提供的 `commercial-readiness-matrix.md` 为准。该审计文件不嵌入客户应用运行时，因此本手册不使用会在打包后失效的相对链接。自动化结果不能替代真实账号验收记录。
