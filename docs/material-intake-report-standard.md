# Echo Founder 素材理解报告标准

版本：v1.0  
日期：2026-07-02  
适用步骤：`content-intake` / `pipeline/intake/`

## 1. 报告定位

素材理解报告不是摘要，也不是成稿草稿，而是后续立项、角度生成、内容拆解和写作可直接使用的事实资产包。

它只回答三个问题：

- 素材里实际有什么。
- 哪些内容可以安全使用。
- 还缺哪些信息，是否足以进入下一步。

报告不得提前替用户写成稿，不替代选题立项判断，不把推断包装成事实。

## 2. 输入范围

支持以下素材：

- 文字、Markdown、聊天记录、会议纪要
- PDF、DOCX、网页链接
- 语音转文字
- 图片 OCR 或人工描述
- 用户口述
- 访谈、演讲、活动记录、业务案例

如果素材来自附件但尚未完成转写、OCR 或正文抽取，报告必须把正文缺口列为阻断项，不得根据文件名或截图印象推断事实。

## 3. 输出位置

素材理解报告写入：

```text
pipeline/intake/{YYYY-MM-DD}-{slug}-intake.md
```

必须通过 `content-runtime` 写入，便于后续步骤自动读取最新 intake 文件。

## 4. 必须章节

报告正文必须包含以下章节标题：

```markdown
# 素材理解报告 · {标题}

## 0. 素材场景
## 1. 人物
## 2. 场景
## 3. 观点
## 4. 情绪
## 5. 案例
## 6. 商业意图
## 7. 不可公开信息
## 8. 外部背景（可选）
## 9. 素材质量判断
```

其中 `0、1、2、3、4、5、6、7、9` 为 runtime 强制校验章节。`8. 外部背景` 只有在用户要求、素材涉及行业数据/近期事件/事实背景时才需要。

## 5. 场景分类标准

每份报告必须先判断素材主场景。可有次要场景，但必须以一个主场景为准。

| 场景 | 用途 | 重点提取 |
| --- | --- | --- |
| 个人履历 / 经验 / 知识分享 | 建立专业身份和可信背书 | 经历、方法论、判断依据、可复用框架 |
| 访谈 / 嘉宾出席 / 演讲分享 | 沉淀高价值对话资产 | 金句、现场细节、人物背景、观点交锋 |
| 个人成长 / 人生心得 | 建立真实感和情绪连接 | 转折点、困境、情绪曲线、价值观变化 |
| 日常工作 / 生活记录 | 把碎片日常变成素材池 | 工作现场、可视化细节、日常冲突 |
| 业务 / 产品增长 / 引流获客 | 转化为商业信任入口 | 用户痛点、产品价值、客户案例、CTA |
| 全球化表达 / 跨境内容 | 面向海外或跨境受众 | 跨文化差异、区域市场、双语表达难点 |

## 6. 逐章内容标准

### 0. 素材场景

必须包含：

- 主场景：从六类场景中选择。
- 判断依据：说明依据素材里的哪些线索判断。
- 次要场景：如无可省略。
- 推荐平台组合：根据素材建议公众号、小红书、视频号中的任意非空组合；最终由操作者确认，未选择的平台不生成。
- 素材来源：原文、链接、访谈、语音转写、聊天记录、图片 OCR、用户口述等。
- 事实边界：区分一手经历、转述、模型推断、外部背景。

阻断标准：

- 没有明确主场景。
- 没有可追溯素材来源。
- 没有事实边界。

### 1. 人物

必须说明：

- 核心人物或说话人。
- 人物关系。
- 人物标签、身份、角色或立场。

要求：

- 不能只写“用户”“客户”“某人”。
- 身份信息必须来自素材或标注为推断。

### 2. 场景

必须包含：

- 时间、地点、背景，至少一个要明确。
- 关键事件链。
- 可视化细节。
- 缺失信息。

要求：

- 事件链要能支撑后续内容结构。
- 缺失信息要显式列出，不用套话补齐。

### 3. 观点

必须包含：

- 明确观点。
- 隐含立场。
- 可争议点。
- 证据位置。

要求：

- 每个重要观点必须标注证据位置，例如原文段落、原话、对话片段、图片或链接。
- 没有证据的观点只能写为“推断”或“待核验”。

阻断标准：

- 没有至少一条可提炼观点。
- 没有证据位置。

### 4. 情绪

必须包含：

- 主情绪。
- 情绪曲线。
- 文本依据或可共鸣点。

要求：

- 情绪判断必须有素材依据。
- 不得只写“积极”“焦虑”等抽象词，要说明情绪从哪里来。

### 5. 案例

必须包含：

- 核心案例。
- 支撑细节。
- 可展开度。
- 可信等级。

可信等级只能使用以下类型：

- 一手经历
- 转述
- 推断
- 待核验

阻断标准：

- 没有核心案例。
- 没有可信等级。

### 6. 商业意图

必须包含：

- 产品 / 服务 / 品牌信息。
- 目标受众。
- 转化路径。

要求：

- 显式商业意图和隐式商业意图要分开。
- 素材没有明确商业信息时，要标注“隐式推断”，不能硬写成事实。

### 7. 不可公开信息

必须包含：

- 隐私信息。
- 商业机密。
- 敏感关系。
- 处理建议。

要求：

- 不能写“无”或空着。
- 即使没有明显敏感内容，也要说明发布时应如何脱敏或避免暴露。

阻断标准：

- 没有具体隐私/商业机密/敏感关系判断。
- 没有处理建议。

### 8. 外部背景（可选）

仅在必要时补充：

- 行业趋势。
- 竞品动态。
- 公开数据或事实来源。

要求：

- 外部研究必须和用户素材分开标注。
- 外部事实必须有来源、时间或口径。
- 不能用外部背景覆盖用户素材本身。

### 9. 素材质量判断

必须包含：

- 信息完整度。
- 可信度。
- 最值得深挖的点。
- 当前缺口。
- 下游可用性。

下游可用性只能明确落到以下判断之一：

- 可直接立项
- 可进入立项
- 需要补素材
- 只适合做灵感备忘
- 不可立项

阻断标准：

- 没有明确下游可用性。

## 7. 质量闸门

系统会对 intake 报告做两层校验。

第一层是结构校验：

- 是否包含必须章节。
- Markdown body 是否非空。

第二层是素材理解质量审计：

- 主场景是否明确。
- 素材来源是否可追溯。
- 事实边界是否清楚。
- 观点是否有证据位置。
- 案例是否有可信等级。
- 不可公开信息是否有处理建议。
- 素材质量判断是否有下游可用性。

阻断问题会导致报告不能进入 `content-validate`。复核提醒可以保留，但下游立项报告必须显式承接。

## 8. 不合格报告特征

以下情况视为不合格：

- 把素材理解写成普通摘要。
- 直接开始写标题、开头或正文。
- 大量使用“待补”“暂无”“不详”“根据实际情况”等占位词。
- 情绪、观点、身份、案例没有证据位置。
- 对不可公开信息写“无”。
- 没有区分事实、转述、推断和外部背景。
- 为了让内容成立而补造客户案例、数据、身份或动机。
- 附件未转写/OCR 时仍然生成确定性结论。

## 10. 验证命令

写入后运行：

```bash
python3 $AIFIOS_HOME/skills/content-runtime/scripts/content_runtime.py \
  --project ~/ai-content-system \
  validate --step intake --file pipeline/intake/{文件名}.md
```

验证通过后，才进入 `content-validate` 做选题立项。
