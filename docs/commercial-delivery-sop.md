# Echo Founder 商业交付 SOP

适用版本：Echo Founder 0.2.0-beta.2

## 1. 交付边界

本 SOP 适用于桌面端 `/production` 的七阶段生产流程。当前运行时使用 Codex 原生本地代码，不依赖 Superpowers。每个 run 先选择任意非空平台组合：公众号、小红书、视频号。平台共享事实底稿、来源证据、人物风格、隐私边界和商业目标，但分别研究、选题、构思和生成；公众号文章不得作为小红书或视频号的生成输入。

平台交付契约：

- 公众号：标题、摘要、完整长文、评论承接、可复制 HTML，以及原稿中已有的授权图片。
- 小红书：发布标题、正文、封面三句话、恰好 P1–P8、结尾互动和标签。
- 视频号：开场钩子、口播稿、镜头提示、字幕重点和发布文案；不创建静态视觉任务。

系统可以在已授权的本机编辑器中填入草稿，但所有公开发送均由操作者完成。不得承诺流量、线索、平台审核通过或其他不可独立验证的经营结果。

## 2. 责任边界

| 事项 | 系统责任 | 操作者责任 |
| --- | --- | --- |
| 素材 | 提取事实、证据、观点、风格、隐私项和缺口。 | 确认授权、公开范围、商业目标，不让模型补写一手事实。 |
| 写作来源 | 作者方式核对已确认的题目、素材与平台；研究方式按已选平台执行 TikOmni 实时研究和 v5 多证据评分。 | 主动选择“按我的题目写”或“帮我找方向”；作者方式不宣称市场验证，研究不足不能静默切换来源。 |
| 内容 | 三条 lane 独立生成并独立通过事实、风格、结构和商业闭环门。 | 审核每个平台的成品，不以一个平台替代另一个平台。 |
| 排版 | 公众号生成完整微信 HTML，小红书生成 P1–P8 观点卡片。 | 审核文字、结构、可读性和页序；有问题时只重做对应平台。 |
| 草稿 | 为已选平台各建立一条权威草稿任务。 | 确认目标账号、文案、图片顺序和“只存草稿”边界。 |
| 发布与复盘 | 保存发布凭证和经确认的表现数据。 | 真人发送、保存真实链接/凭证，确认可写入长期学习的结论。 |

## 3. 开始前检查

1. 为客户建立独立项目，导入已授权素材并确认隐私禁区。
2. 选择本期平台组合及写作来源；首次可只选一个平台，已有题目时选择“按我的题目写”。生成方案和正文前须配置可用模型，保存配置本身不调用模型，连接测试可能产生服务费用。
3. 只有选择“帮我找方向”时才需要 TikOmni。某一研究平台不可用时，可继续有可追溯证据的平台，或主动重选平台及来源并重新确认；不得把不足样本显示为“爆款对标”，也不得静默使用作者方式绕过研究。
4. 确认本机是否安装 `md2wechat`。可用时优先使用；不可用时自动使用 Echo Founder 内置排版，不阻断生产。
5. 本流程不配置生图账户、不生成两套方向，也不产生文生图费用。`md2wechat` 作为外部可选工具不随 App 分发，商业使用前需另行确认其许可证。

在正式交付前观察首位真人使用时，使用[首篇真人试用任务与记录表](first-user-trial.md)记录本人操作、协助、编辑投入、成品采用和下一篇使用。当前表格为空，不能作为已完成客户验收的证明；它也不替代下文发布门禁。

## 4. 七阶段流程

### 阶段 1：素材与边界

- 生成共享事实底稿：原始素材摘要、可公开事实与证据、核心观点、人物表达风格、禁止公开内容、商业目标。
- 不生成公众号母稿，也不提前决定其他平台的表达结构。

### 阶段 2：写作来源与平台方案

- “按我的题目写”核对作者题目、已确认素材和已选平台，保存不可变的作者素材记录，明确本期未做平台研究；方案仍由模型生成并由作者确认。题目、素材或平台变化后需要重新核对。
- “帮我找方向”对每个已选平台分别研究，使用本平台公开样本判断选题角度、用户情绪和原生结构。
- 爆款内容雷达不按账号类型或内容目标过滤，完整保留“可验证爆款”“高潜样本”“相关样本”“指标不足”四类公开候选。
- TikOmni v5 只有在证据、表现、相关性、综合分和强比较信号同时达标时才显示“可验证爆款”；其余显示“高潜样本”“相关样本”或“指标不足”。
- 研究方式下，操作者确认各平台方向后冻结本 run 的研究快照，新增平台必须补做该平台研究；作者方式下则绑定已确认作者素材与方案，不伪造研究快照。

### 阶段 3：平台原生成稿

- 三个平台分别从共享事实底稿生成，不发生母稿改写关系。
- 每条 lane 独立通过事实追溯、人物风格、平台结构和商业闭环质量门。
- 小红书必须恰好包含 P1–P8；视频号必须没有静态视觉任务。

### 阶段 4：平台完整发布件

- 新任务固定使用 `stable`，不提供 AI 生图选项，不读取生图账户，也不创建付费图片生成请求。
- 公众号保留原稿中已有的授权图片，优先调用本机 `md2wechat` 生成完整微信兼容 HTML；CLI 不可用、未配置或调用失败时自动回退到内置 `dbs-wechat-html`，不强制生成后台封面或正文插图。
- 小红书直接由本地 HTML/SVG 渲染器把独立成稿生成 P1–P8 观点卡片。
- 视频号自动跳过，不创建静态视觉任务。
- 系统只提供一套推荐发布件；排版修改生成新 revision，不要求比较视觉方向。

### 阶段 5：平台草稿确认

- 每个已选平台形成一条权威草稿任务：公众号 1 条、小红书 1 条、视频号 1 条。
- 公众号草稿包含完整 HTML 和原稿中已有的授权图片；小红书草稿包含 P1–P8、封面三句话和标签；视频号草稿只包含脚本与发布字段。
- 系统只填入草稿，不点击公开发布。验证码、风控、设备确认和完成状态不明时停止并转人工。

### 阶段 6：发布结果

- 操作者在平台内完成发送后，逐项保存链接或可验证凭证、时间、内容哈希和排版版本。
- 单个平台失败时继续处理其他平台；局部重试不得改变已采用资产。

### 阶段 7：周复盘

- 只汇总已经人工确认发布的条目和可追溯指标。
- 模拟数据、缺失数据和草稿不得形成长期学习结论。

## 5. 排版与插件边界

- 公众号交付一个完整、可复制的 HTML 排版文件；原始素材中的授权图片和证据图可保留在正文中。
- 小红书先完成 P1–P8 视觉叙事，再由本地引擎统一渲染尺寸、色板、字体和安全区。
- `md2wechat` 不存在、超时或输出不安全时，系统自动回退到内置排版并记录实际 renderer。
- 新任务不会调用 `baoyu-image-gen`、付费生图路由或 AI 概念图；旧视觉配方只读兼容。

## 6. 发布门禁

内部候选至少需要通过 TikOmni 45 条人工标注、方法论/人物故事/研究分析三类全流程、九条真实平台草稿和冻结 DMG 验收。排版验收还要证明公众号 HTML 可复制、小红书恰好 P1–P8、视频号正确跳过，以及 `md2wechat` 失败时内置排版仍能完成交付；这些内部检查通过也不等于正式商业验收通过。

现有 `echo-founder.real-account-acceptance.v3` 绑定的是旧付费生图设计，只保留历史验证语义；本次改变不能沿用 v3 宣称正式商业验收。新的固定 `stable` 排版验收契约完成审查前，本候选只能作为内部版。

设置页不再向普通用户展示生图账户配置。旧图像路由、benchmark 和 v3 验收工具仅保留兼容与审计用途，不属于当前七阶段生产入口。

```bash
make version-check
make commercial-readiness-source
make test
make pytest
make runtime-contracts
make ui-runtime-gates
make content-loop-check
```

完整桌面构建、安装、恢复和 soak 门禁以 [RELEASE.md](../RELEASE.md) 为准。冻结 DMG 后如修改任何代码，必须重建并重新执行三类完整验收。

## 7. 历史迁移

旧五平台、母稿和 `1+2+3` 内容只允许只读迁移最终发布内容、已采用视觉、发布链接和规范化表现数据；不进入新 run，也不得重新成为 UI 默认路径。

```bash
python3 scripts/migrate_final_publication_history.py --project ~/ai-content-system --dry-run
python3 scripts/migrate_final_publication_history.py --project ~/ai-content-system --apply
```
