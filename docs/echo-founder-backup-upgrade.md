# Echo Founder 项目备份、恢复与升级

本说明适用于 Echo Founder `0.2.0-beta.2`。项目数据与应用程序彼此独立；手动覆盖应用不应删除项目，但升级前仍必须备份。

新安装默认使用 `~/Echo Founder/` 作为项目目录。已保存的项目路径、显式 `AIFIOS_PROJECT` 和仅存在的历史默认目录 `~/ai-content-system/` 继续兼容；应用不会自动重命名或合并旧目录。

## 备份格式

在“设置 → 项目备份与恢复”中选择“导出目录包”。导出物是一个以 `.aifios-backup` 结尾的目录，格式 schema 为 `aifios.project-backup.v1`，主要包含：

- `manifest.json`：应用版本、项目 schema、创建时间、文件清单、大小和 SHA-256；
- `data/`：通过清单校验的项目文件。

`.aifios-backup` 是历史兼容扩展名。请把整个目录视为一个不可拆分的备份包，不要改名其中的文件、手工修改 `manifest.json` 或只复制 `data/`。SHA-256 用于发现意外损坏，不是第三方签名或来源认证；只导入由受信任 Echo Founder 客户端创建并由你本人保管的备份。

备份明确排除：API Key、TikOmni Token、平台凭据、macOS 钥匙串、浏览器 Cookie/会话、日志、缓存、构建产物、Git 数据与临时文件。旧版配置中可能残留的密钥字段只会从导出的备份副本中剔除，不会修改当前项目。

只有旧版专属源码指纹、目录结构和未迁移 schema 同时匹配时，项目才会被识别为“源码与数据混合目录”；迁移后该来源会写入项目 marker，避免普通客户项目仅因同名目录被误判。此时 `manifest.json` 的 `projection` 为 `legacy-mixed-checkout-data`：备份明确排除已知旧运行时源码、测试代码和构建脚本，但保留工程文档、示例、非代码测试资料，以及所有未知自定义目录和根级 Excel，并逐文件执行凭据扫描。因此 `brain`、`materials`、`pipeline`、`runs`、`sessions`、`deliveries`、`config` 等业务数据不会因白名单缺失而静默丢失。恢复端会校验清单中的路径是否符合其声明的 projection。原目录始终保留不动。普通项目使用 `complete-project`，不会因为顶层目录名是 `tests` 或 `.github` 而静默丢失文件。

## 导出验证

1. 打开当前项目，确认没有正在进行的写入任务。
2. 进入“设置 → 项目备份与恢复”。
3. 点击“导出目录包”，选择一个不在当前项目目录内的位置。
4. 等待界面报告文件数并完成。
5. 确认备份目录同时存在 `manifest.json` 和 `data/`，再复制到受控存储。

不要通过电子邮件或公共网盘传输包含客户素材的备份，除非客户已经批准对应的数据处理方式。

## 恢复

1. 在 Echo Founder 中打开“设置 → 项目备份与恢复”。
2. 点击“验证并恢复”，选择完整的 `.aifios-backup` 目录。
3. 选择一个全新的目标目录。系统不会直接覆盖当前项目。
4. 系统会拒绝路径穿越、符号链接、重复或大小写冲突的路径、缺失文件、摘要不匹配和不支持的 schema。
5. 全部校验通过后才会切换到新项目并重启本地服务。
6. 重新配置模型、TikOmni 和平台凭据，并重新完成浏览器/手机授权。

若校验失败，保留原备份与当前项目，不要手工把未验证的数据覆盖进去。

## Schema 迁移与自动保护

应用检测到需要升级的旧项目 schema 时，会先在本机项目备份目录建立带时间戳的 `.aifios-backup`，完整备份成功后才写入新 schema。迁移失败时应停止启动新 schema，旧项目和升级前备份继续保留。

自动备份不会替代客户自己的离机备份，也不会迁移钥匙串和账号会话。

## 手动升级

本期不提供自动更新器。收到新 DMG 后：

1. 在旧版本中导出并验证项目备份。
2. 退出 Echo Founder，确认菜单栏和活动监视器中没有残留进程。
3. 核对新 DMG 的文件名、版本与 SHA-256。
4. 打开新 DMG，将 `Echo Founder.app` 拖入“应用程序”并覆盖旧应用。
5. 首次打开新版本时按 [安装说明](echo-founder-installation.md) 完成 Gatekeeper 人工确认。
6. 打开原项目，等待健康检查与必要的 schema 迁移完成。
7. 验证素材、审批、视觉、11 项草稿队列、发布台账与周复盘记录。
8. 验证完成前不要删除旧 DMG、旧应用副本或升级前备份。

## 回滚

如果升级后健康检查或迁移失败：

1. 退出新版本，不要继续对失败迁移目录写入。
2. 重新安装此前验证过的旧版本应用。
3. 通过“验证并恢复”把升级前备份恢复到一个新目录。
4. 重新配置所有凭据和账号会话。
5. 将脱敏诊断包、应用版本、项目 schema 与失败时间提交给交付方。

不要用文件管理器直接把部分旧文件覆盖到新项目中，这会破坏 run、审批、视觉哈希和发布台账之间的完整性。
