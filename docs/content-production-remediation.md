# Active Content Production Remediation

状态：活跃验收基线  
适用版本：Echo Founder 0.2.0-beta.2
运行方式：Codex 本地工作区、Python、Next.js/Electron

本文件定义当前产品必须满足的生产边界。当前运行时使用 Codex 原生本地代码，不依赖 Superpowers。`docs/superpowers/`、旧五平台队列、母稿和 `1+2+3` 只用于历史追溯，不是新 run 的运行入口。

## 1. 第一性原则

```text
授权素材 + 公开证据 + 人物风格 + 隐私边界
  -> 共享事实底稿（不是母稿）
  -> 已选平台各自实时研究、选题和结构判断
  -> 公众号 / 小红书 / 视频号独立成稿与独立质量门
  -> 公众号 stable HTML 排版与小红书本地卡片；视频号跳过静态排版
  -> 每个平台一条草稿任务
  -> 人工公开发送与凭证
  -> 可选的表现学习
```

共享的是事实与约束，不共享文章结构。局部失败只影响当前 lane 或资产；结果不明的外部操作禁止盲目重试。

## 2. 七阶段产品契约

`/production` 是日常入口。阶段 2–6 是服务器校验的人工硬停点。

| 阶段 | 系统产出 | 人工控制 |
| --- | --- | --- |
| 1. 素材与边界 | 共享事实底稿、授权/隐私边界、缺口、平台组合 | 校正一手材料与商业目标。 |
| 2. 平台研究与方向 | 各 lane 的 TikOmni 快照、角度、结构和理由 | 分平台确认方向与证据边界。 |
| 3. 平台原生成稿 | 公众号、小红书、视频号各自完整交付字段 | 分平台确认，不接受母稿改写。 |
| 4. 平台排版 | 公众号完整 HTML、小红书 P1–P8 本地卡片、排版 revision | 按平台预览并确认完整发布件。 |
| 5. 平台草稿 | 每个已选平台一条权威草稿任务 | 确认目标账号、文案、排版资产和顺序。 |
| 6. 发布结果 | 链接/凭证、时间、内容与排版资产哈希 | 真人发送后逐项确认。 |
| 7. 周复盘 | 缺失指标、复盘候选和学习计划 | 手填指标并确认长期结论。 |

平台组合支持全部七种非空选择。研究后新增平台必须补做该平台研究；取消平台不得删除历史证据。

## 3. 平台原生交付

- 公众号：完整长文、标题、摘要、评论承接、可复制 HTML，以及原稿中已有的授权图片。
- 小红书：发布标题、正文、封面三句话、恰好 P1–P8、结尾互动和标签。
- 视频号：开场钩子、口播稿、镜头提示、字幕重点和发布文案；静态视觉任务数必须为 0。

质量门必须证明公众号未成为小红书或视频号的生成输入。不同 lane 可独立失败、重试、通过和进入草稿。

## 4. TikOmni 爆款识别 v5

- 爆款内容雷达只按行业/主题和平台检索，不再按账号类型或内容目标提前裁剪候选池；这些信息可以在后续创作阶段用于表达适配，但不能改变公开证据。
- 雷达保留并展示全部候选类别：“可验证爆款”“高潜样本”“相关样本”“指标不足”，同时展示判定理由与原始公开指标。
- 缺失指标保持未知，禁止转换为 0。
- 未来时间、无公开 URL、无有效发布时间或有效表现指标少于两个时显示“指标不足”，不得进入爆款排序。
- 表现分：绝对体量 35% + 有曝光分母时互动率 25% + 同批百分位 20% + 作者历史提升 20%。
- 总分：表现 55% + 查询相关性 20% + 新鲜度 10% + 证据完整度 15%。
- “可验证爆款”同时要求证据 ≥80、表现 ≥75、相关性 ≥60、总分 ≥80、至少两个独立表现指标，以及互动率/批次百分位/作者提升中的一个强信号。
- 60–79 分为“高潜样本”；其余为“相关样本”或“指标不足”。UI 必须展示判定理由和原始公开指标。

正式校准每个平台至少 15 条人工标注，总数不少于 45；未来时间、零指标和缺指标误报为爆款必须为 0，“可验证爆款”人工精度必须不低于 90%。不达标时统一降级为高潜。

## 5. 固定 stable 排版与本地渲染

- 新任务的 `visual_preferences.mode` 固定为 `stable`；产品不提供 AI 生图选项，不读取生图账户，也不调用图片生成服务。
- 公众号保留原稿中已有的授权图片，优先使用本机 `md2wechat` CLI 生成完整 HTML 与手机预览；CLI 不可用、未配置或调用失败时自动回退到内置 `dbs-wechat-html`，不得强制生成头图或正文插图。
- 小红书由本地 HTML/SVG 渲染器把独立成稿生成恰好 P1–P8 八张卡片，文字层级、色板、留白和图形元素均由确定性排版完成。
- 每个平台只展示一套推荐发布件；用户修改排版时生成新 revision，已确认版本不得静默覆盖，也不进入视觉方向或 AI 插画比较。
- 真实照片、截图、数据图与其他授权素材可按原文位置保留；来源与证据边界必须可追溯。
- 取消、关闭 App 或重启后，已通过的排版 revision 必须可恢复。

旧任务中的 AI 概念图、付费路由、账户策略和预算记录仅供只读兼容与历史审计，不得进入新任务或被解释为当前产品能力。

## 6. 草稿、发布和恢复

- 已选平台各生成一条草稿任务；方法论、人物故事、研究分析三类验收内容各跑一轮且三平台全选时，累计九条真实账号验收草稿。
- 公众号优先官方草稿接口，小红书和视频号使用操作者授权的本机路径。
- 所有公开发送由人点击；系统不保存 Token、Cookie、密码或浏览器会话到项目。
- 单平台失败不取消其他平台；明确失败可局部重试，未知完成状态必须人工核账。
- 发布结果必须绑定真实链接/凭证、当前内容哈希和已确认排版版本。

## 7. 版本与验收

新任务继续使用 `echo-founder.platform-native-package.v2` 和 `aifios.visual-recipe.v2`，但后者只允许 `stable` 本地排版。旧包、`visual-recipe.v1` 及 v2 中的 AI/付费字段只读兼容。

| 要求 | 可验证证据 |
| --- | --- |
| 平台隔离 | 七种平台组合测试；公众号不成为其他 lane 输入。 |
| P1–P8 | 页数、页序、封面三句话、正文和标签完整。 |
| 视频号无视觉 | 静态视觉任务数为 0。 |
| 固定 stable | 新 run、接口与发布件均不能启用 AI 生图模式或创建付费操作。 |
| 公众号排版 | `md2wechat` 可用时生成完整 HTML；不可用或失败时由内置排版完成同一交付。 |
| 本地卡片 | 小红书由本地渲染器生成恰好 P1–P8，不依赖图片生成服务。 |
| 爆款精度 | ≥45 条人工标注、无无效证据误报、精度 ≥90%。 |
| 真实流程 | 方法论、人物故事、研究分析各覆盖三平台并进入草稿。 |
| 冻结产物 | 干净源码、App/DMG manifest、SHA-256、安装/恢复/soak 通过。 |

```bash
git diff --check
make version-check
make test
make pytest
make runtime-contracts
make ui-runtime-gates
make content-loop-check
make commercial-readiness-source
```

现有 `echo-founder.real-account-acceptance.v3` 验收的是旧付费生图设计，只保留历史证据解释能力，不能用于判定当前候选通过。面向固定 `stable`、`md2wechat` 与本地卡片的新正式验收 schema 完成独立评审和真实账号验收前，本候选只能标记为内部版，不得宣称正式商业就绪。
